## 验证资源

- 使用 .trellis/tasks/09-05-m0-rubric-anchors-evidence/research/real-sample-validation.md 指定来源，经 C1 代码重建；原始日志和样本只读。
- PostgreSQL 测试库、端口、Worker 和产物均为本次独占；只停止/清理由本次创建且身份已确认的资源，不强杀固定端口监听者或整个 Docker 容器。
- 使用生产构建前端验证 rewrite/SSE；明确 API、Worker、模型、SDK、仓库 SHA 与实际数据库目标。
- 私有原文证据按父任务 task-map.md 的非 Git 产物保存策略留存；后续验收不依赖已删除 worktree，公开报告只含脱敏统计与定位。

## 测试矩阵

| 类别 | 关键场景 | 必须证明 |
| --- | --- | --- |
| 合同与审改 | 初始建议分、未列出的人工分数、依据修改、取消/确认重生成 | 全字段保留，无白名单，无自动覆盖 |
| 真实传输 | 生成中订阅、晚订阅、刷新、隐藏/恢复、终态事件丢失 | 实际增量先于完成，原文可回放，最终状态来自业务保存 |
| 持久恢复 | Worker 中断、图完成但提交失败、重复输入 | 同 thread 续跑，不重复输入，不把 UI 恢复当图恢复 |
| 并发与权限 | 同线程双写、失租、过期 revision、跨题定位 | 旧运行不能继续写，工具/事件/读接口不越界 |
| 完整删除 | 多次重生成历史、部分 thread 删除后崩溃、checkpoint 不可用 | 幂等继续清理，所有在线副本无残留，控制作业不误删自身 |
| 无模型清理 | Provider 网络/初始化失败 | 删除不调用模型，不被误投影生成失败 |
| 真实样本语义 | 有效材料时点、老师要求/AI 推定、引用与独立预期 | 不用私有思考或过期要求作为标准，不伪造缺失版本 |

## 证据合同

- 以源 case/hash -> batch/question -> operation/attempt/thread -> checkpoint/event -> 最终结果/删除结果建立关联，实际 Worker 身份不只来自 health 或环境变量。
- 断言来源在模型运行前固定；如果修改预期必须说明原依据与变更原因，不从输出直接生成新 golden 来消除失败。
- 自动合同结果、Agent 对业务来源的审阅和老师实际认可分栏，未发生的人工确认不得填成通过。
- 记录版本、调用/重试/摘要次数、token、耗时和失败分类；样本不足时保留原始测量，不伪造代表性的 P95 或修订负担。
- 如做同模型/同材料/同合同的离线策略对照，仅作为隔离试验，不恢复多个生产路径。

## 缺陷与版本管理

- 修复通过最小复现和新增回归进入本任务分支，受影响 API/类型/规格同步；不能以测试任务为由修改任务外模块或恢复兼容逻辑。
- 检查最新正式 SDK；发生升级时重新跑 C2 原语与 C3/C4 集成门。接口或范围变化先同步父/子设计，不绕过验收。
- 保持 shared_database_reset_allowed=false；测试库故障注入不能扩展到 C5 才被授权切换的当前项目两库。
