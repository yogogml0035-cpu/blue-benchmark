## 2. 使用当前推荐的流式 API，验证具体版本合同

- 直接读取当前官方 Markdown 正文：Deep Agents Streaming 文档推荐 Event Streaming，并说明它于 Deep Agents v0.6 引入；Deep Agents/LangChain Event Streaming 文档给出 `stream_events` / `astream_events`、`version="v3"` 示例。本轮所读正文未见 Beta/preview/experimental 标记，不沿用初步核查中未经正文支持的 Beta 断言，也不据此替框架作无风险保证。
- 它提供可增量消费的消息文本、工具调用/结果、custom 事件和最终状态投影，适合把执行过程接入 UI。同步与异步入口均存在，不必为了“高级”先把当前同步 Worker 全部改成异步。
- 当前官方文档还保留 `stream` / `astream` 配合 `stream_mode` 的底层模式。最新 SDK 与具体 API 合同是两件事；不能把旧例子当唯一入口，也不能把官方推荐理解成所有网关都已验证可用。
- 本任务优先验证官方当前推荐 Event Streaming；锁定 SDK 后用该版本的发布包、契约测试确认事件形状。若接口存在实际阻塞问题，先记录证据和替代设计，不降级 Deep Agents 或在生产保留两条互不一致的进度链。
- 一份完整 rubric 的结构化输出可能通过工具调用返回，不能假定每个阶段都有自然语言 token。必要进度由真实工具/阶段事件产生；模型额外的公开短反馈可以流式呈现，不能把原始 JSON 参数碎片当阅读体验。

## 4. 三种信号必须区分

| 信号 | 示例 | 谁提供事实 |
| --- | --- | --- |
| 执行事件 | 开始读取某条反馈、完成材料读取、开始候选生成、进入引用校验、正在修订、正在保存 | 确定性的 Worker/工具/校验器；只有实际发生才更新阶段。 |
| 模型公开反馈 | “正在核对这条反馈是否要求更高的新颖性” | 模型允许公开的简短工作说明；标为说明，不把自述当作已完成的工具事实。 |
| 连接与活性 | 浏览器重连、Worker 最近续租、模型请求等待、上次有效进展时间 | 传输和作业状态；心跳不等于语义工作有推进，更不等于已完成某阶段。 |

- 展示阶段和真实局部计数，例如已处理反馈数量；只有确知本阶段总数时才展示分母。整个自主任务通常不知道剩余工作量，不能把字符量、计时器或六个标题映射成假 80%。
- 阶段允许返回材料核查或再次修订，不做只能前进的固定百分比。排队、读取、生成、校验、修订、保存只是可读状态词，不是必须每轮逐个走完的仪式。
- 没有新 token 时如实显示“等待模型响应”和最后进展时间；不能用持续动画宣称模型仍在完成有效工作。网络断开、任务失败、重试是不同状态。
- 公开短反馈、真实工具状态可以展示；不直接透传模型 reasoning 块、系统 Prompt、认证信息、原始工具参数/完整响应或未经授权的材料。这里不是展示模型私有推理链。

## 5. 推荐的端到端结构

```text
已有 Worker 执行本题 job
  → 最新 Deep Agents Event Streaming
  → 受控事件适配器：来源分类、字段白名单、长度限制与脱敏
  → 本 job 的有界进度记录 / 当前快照
  → 鉴权后的 FastAPI 同源 SSE
  → 题目页生成时间线

完整 rubric → 校验 → 现有 CAS 原子保存 → 成功事件 → 页面读取权威结果
```

- 首选 SSE 是因为本次主要是后台向浏览器单向发送反馈；不为模仿桌面端引入 WebSocket 聊天系统、桌面应用或第二套 Agent 执行入口。这是工程提案，不是用户必须选择的技术项。
- 事件模型由 Pydantic 定义并进入 OpenAPI 合同，前端由生成 TS 派生；不把框架原始事件结构直接暴露为产品 API。候选字段：`operation_id`、`attempt_number`、`content_revision`、`sequence`、`kind`、`stage`、`message_id`、`text`、时间；最终字段在实现前锁定。
- 事件由服务注入 job/attempt/revision，模型不能自报其他题目 ID。追加时检查当前作业、有效尝试与 fencing；旧 Worker 的迟到事件不得污染新一轮界面。
- adapter 仅向注入的 `ProgressSink` 报告，不直接写业务数据库。服务层持有 sink 与进度 Repository；最终业务成功仍以 CAS 保存及题目状态为准，不能收到模型结束就提前显示完成。
- 公开消息按 thread/operation/attempt/sequence 关联并幂等消费，小批合并、不逐 token 一行写库，但完整保存已授权公开的原文。先保存后发送，分页/快照限制界面负担，不以摘要或截断替代原文。
- 前端断开只取消订阅，不取消 job。重连/刷新先取快照再从 cursor 继续，不能触发第二次生成。后台另按 runtime-design.md 从 checkpoint 续跑；未完成模型请求重试须保留旧公开片段并标明 attempt，不承诺逐字断点续写。
- 每次订阅和重连验证登录态、题目归属及指定 operation 与题目的关系；URL 不带凭证。会话失效时停止显示受保护的新事件，不因为 EventSource 自动重连而绕过授权。
- 完成记录丢失或晚订阅时，由最新题目/job 状态恢复终态；已被替换的 job 不继续流入当前题目。长连接不占用跨整个任务的数据库事务。
- 传输保活和 Worker 活性监测独立，实际代理缓冲、读取超时、浏览器后台恢复、流式工具参数和 provider 错误需集成验证。没有真正流式到达时不能用前端打字动画冒充。

## 6. 长等待与安全停止

- 用户已接受很久的等待：撤回“必须几十秒/几分钟内结束”的产品目标，不为追求短时长削减必要材料核查。
- 可以长时间生成不代表无限费用、无限重试或永久死循环授权。仍区分单请求超时、传输掉线、Worker 失租、重复无进展和总调用安全上限；具体阈值是待验证工程预算，不替用户设一个新的短等待上限。
- 有真实推进时 UI 持续呈现阶段和反馈；只有活性心跳但无新进展时如实说明。安全终止或实际失败时显示原因及已有的明确重试入口，不一直转圈等用户猜测。
- 本轮不新增取消、暂停、继续生成或用户干预中间草稿的业务操作；这些不是展示进度的必需条件，也未获产品确认。

## 7. UI 草案与验收

- 在现有“评分维度”区域显示“生成中 / 当前阶段 / 已用时间”，下面显示真实步骤与流式公开短反馈；运行态可动，但 reduced-motion 关闭动效后文字状态仍完整可理解。
- 新内容合并更新，老师查看较早反馈时不抢滚动位置；可提示有新反馈。读屏按阶段节流通知，不逐 token 播报。
- 中间输出不进入可勾选、可保存的正式维度编辑器；必须完整生成、校验、原子保存后才进入原审改流程。动态生成过程不能冒充最终规则。
- 验收覆盖：长时间无 token、正常长任务、重新读材料、校验修订、provider 重试、断线重连、页面刷新/隐藏恢复、重复和乱序事件、失租/旧 job、权限失效、终态事件遗漏、SSE 代理缓冲、reduced-motion 和读屏。
- 同步和异步流只选真正走通现有 relay 的实现；模型直连 demo、SSE 本地通路和 fake 动画均不能替代 production Worker → API → 实际代理 → 浏览器的真实验收。

## 8. 已确认的业务范围

用户已明确需要完整公开过程与上下文留存，不再询问是否回看，也不只保留简短记录。本题执行连续性现在接入 PostgreSQL checkpoint；已确认要求只作用于本题，不自动检索或参考相似题、不接跨题 Store。旧测试库一次性清理已获授权，真实 `.local-samples` 用于集成/冒烟；日常删除题目时一并清理完整过程与上下文、保留原确认门禁也已确认。题目存在时不自动到期清理，不把运行记录等同于旧评分标准恢复或全部私有推理公开。
