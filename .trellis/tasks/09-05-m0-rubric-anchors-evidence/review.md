# M0 评分维度重构：最终审阅稿

状态：2026-09-06 用户已明确批准实施本任务树（父任务 + C1-C5）。D01-D23 的业务决定已记录；本文件不是实施、测试或数据库删除的完成报告。

已按用户要求拆成原父任务 + C1-C5 五个原生 Trellis 子任务。父任务负责共享需求和最终验收，不直接启动业务实现；task-map.md 给出依赖、所有权和 worktree 门禁。本次拆分不构成实施批准。

## 目标

老师能看懂评分维度及最低通过分的依据，方便审改；较长生成有真实可回看的进度，运行可恢复，删除不会在平台在线存储中遗留题目原文。

## 本次范围

- 完整评分项：具体维度、0–10 整数通过分、少量关键分数描述及 AI 建议分描述、维度依据与通过分依据；分清老师明确要求与 AI 推定。
- 原有勾选/编辑/整数输入不变。全部内容可改，普通编辑保留关联内容并提示核对；主动整套重生成在明确确认后才替换，包括人工修改。
- 不额外增加人工新建维度必须补齐 AI 辅助说明的发布门槛，也不新增一套独立核对审批；生成结果完整性与老师编辑保存的校验分开。
- 最新正式 Deep Agents 作为受限生成运行时，按需读取本题材料，联合输出完整候选并做有界校验/修订。不是为每个字段开启互不相干的 Agent，也不强迫所有题走固定长流程。
- 真实可读流式加载和完整公开历史；同题 thread、StateBackend 与当前 Docker PostgreSQL checkpoint 持久化。浏览器重连、Worker 恢复和主动重生成各用正确语义。
- 题目删除保留鉴权、版本、状态和标题确认门禁；一并清理该题所有材料、维度、公开过程、历次 thread/checkpoint 与受控运行副本。跨库清理可重试，全部完成才显示删除成功。
- 当前项目旧测试数据已授权在切换时一次性清理；`.local-samples` 原件保留。两组真实来源生成可追溯测试输入，完成集成、冒烟、浏览器闭环和 main 复验。

## 不做什么

- M1 在线新稿生成、实际评分或聊天入口；只提前验证中断/回复恢复的运行协议。
- 自动检索相似题、跨题规则继承、跨题 Store、全局老师偏好学习。
- 旧新两套维度合同、旧数据转换/回填、隐藏旧入口、假流式、后台自动改写人工内容。
- 自动到期删除现存题目的历史、自动备份产品或原始样本销毁；一次性旧测试库清理不扩展到未来新数据。

## 实施顺序

1. C1 真实样本与基线：形成可重建六材料输入、来源与独立预期，保护原件，不改变生产语义。
2. C2 持久运行基础：在独占验收环境提供并验证最新 Deep Agents、受限工具/流式、PostgreSQL checkpoint、恢复和清理原语，不提前开放另一生产入口。
3. C3 业务一次性切换：完整 rubric/数据库/API/前端、生产 Worker/消息/SSE/恢复、关联删除和旧路径删除一起交付，并通过最小真实闭环。
4. C4 系统验收与加固：用两组真实来源扩大集成、冒烟、并发故障、恢复与删除回归；不能代替 C3 补齐基础功能。
5. C5 本地切换与交付：完成安全 reset 工具及最终 main 复验，再按一次性授权切换当前两库与实际服务，保留源文件并交付可重新上传的环境。

各子任务分别从依赖已合入并复验的 main 创建独立 worktree；全部完成后由父任务核对总验收。C3 的跨层步骤不可拆成以临时兼容维持的半套生产交付。

## 验收底线

- 初始 AI 结果必须解释建议分；老师改成未列出的整数仍能保存，不自动补档或覆盖。所有辅助内容刷新后保留。
- 引用来自本题真实材料，来源和老师要求/AI 推定分类正确；不拿 AI 自述、思考注记、工具元数据或过期反馈冒充老师标准。
- 生成未完成时浏览器已收到真实增量；完整公开原文可回放，关闭页面不取消生成。恢复不重复初始输入，不覆盖新材料或人工修改。
- 删除前原门禁全部通过；删除后直接检查两库、消息存储和受控缓存无该题原文/状态残留。清理失败/Worker 中断后可继续，旧写者不能写回，其他题不受影响。
- 财报供稿和 MEGA 新闻稿两组各至少一个证据完整 case 走真实业务闭环。真实测试使用 PostgreSQL、production Worker 和真实 Provider；SQLite/fake、HTTP 200 或历史 PASS 标记不能替代。
- `git diff --check`、`make test`、`make build`、适用的 E2E、真实样本集成/冒烟及 main 复验均有本次证据；源文件 hash 保持不变，失败与未覆盖项如实报告。

## 实施时验证

- 最新 SDK/relay 的流式、工具调用、结构化结果、checkpoint 加密与恢复，以及跨库删除必须按锁定版本实测；失败时修复或报告阻塞，不降级旧版本或以 fake 替代真实验收。
- 工程预算基于现有超时/重试配置、实际样本体量先设有界上限，再由隔离试验校准，包含 SDK 重试、摘要和作业重试。允许长等待，不把安全预算改成任意短体验门槛，也不把等待授权当作无限费用授权。
- 缺失版本材料不伪造：例如当前样本仅有 v2 实体讲稿时，不能声称已验证 v6 全文一致性。取证完整的子场景，未覆盖项单列。
- 删除承诺覆盖平台管理的在线数据和缓存，不是远程擦除用户另存文件或 Provider 自身日志；离线回滚不得重新暴露已删除内容。
