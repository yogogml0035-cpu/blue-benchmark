# Benchmark M0 后端接口与上传 Skill 重构

## Goal

将当前项目重构为以后端题库能力和本地上传 Skill 为核心的 M0：业务老师在本地 Agent 中完成真实任务后，调用仓库内 Skill，从当前完整可见上下文整理评测题，经老师确认后批量上传；后端保存题目并自动生成评分维度，为后续新前端提供完整 API。

本任务当前只做需求、技术设计和实施计划。用户另行明确批准前，不修改产品代码、不删除前端、不创建 Skill，也不运行 `task.py start`。

## Product scope

### 统一题库与场景文件夹

- 平台只有一个包含全部题目的统一题库。
- 待处理题目和已发布题目显示在同一题库中，通过状态、筛选和下一步动作区分。
- 统一题库下可以创建多个场景文件夹。
- 场景只用于归类，不保存品牌规则、目标 Skill、评分偏好，也不参与评分维度生成。
- 每个场景拥有独立上传凭证；Skill 当前绑定一个场景凭证，题目自动进入对应场景。
- M0 不支持题目跨场景移动或复制。

### 一道评测题的六类材料

1. **题目**：业务老师实际输入给本地 Agent 的任务要求、问题或 Prompt。这是被评测的真实输入，不是用例标题。
2. **参考样例**：业务老师本次提供给 Agent，且 Agent 实际读取过的文件、附件、数据或内容。Agent 根据完整上下文整理出与当前题目有关的信息，经老师确认后上传。
3. **Bad case**：本次真实执行中产生且被老师明确否定的结果，可以为 `0..N` 个，不能由 Skill 合成。
4. **老师反馈**：必须绑定具体 Bad case，保存老师反馈原话和经老师确认的原因整理，保留“哪个结果因为什么不好”的关系。
5. **标准答案**：老师最终认可的结果，是高质量参考而不是唯一措辞答案。每道题必须有独立标准答案。
6. **记忆材料**：由本地调用平台 Skill 的 Agent，从本次任务实际加载的记忆中自动筛选出的相关、安全原始片段。来源可以是业务 Skill 记忆、用户记忆、本地项目记忆或其他记忆机制，不绑定某个 Skill。

每道测试用例保留一个由本地 Agent 根据上下文生成、管理员可修改的简短“用例标题” `title`，用于题库检索和快速识别。它不属于六类材料、不替代题目正文，也不参与评分维度生成；单独修改标题不触发评分维度重新生成。

### 材料与隐私边界

- M0 只上传和保存文本，不保存 PDF、Word、图片、ZIP 等原文件，不建设服务端解析、解包、OCR 或附件对象存储。
- 参考样例只来自老师本次提供、且 Agent 实际读取过的内容；不得扫描未读取文件，也不得根据文件名猜测内容。
- Agent 可以整理参考样例，但不得加入来源不支持的信息，最终文本必须经老师确认。
- 记忆材料按“是否在本次任务中实际加载并进入上下文”判断，不按业务 Skill、Agent 或项目来源划分所有权。
- 业务 Skill 记忆、用户自己的长期记忆、本地项目记忆等，只要实际进入本轮上下文，都进入 Agent 的候选判断范围。
- 记忆材料只保存原始片段，不摘要、不润色、不改写。
- 本地 Agent 负责排除与当前题目无关或包含敏感信息的记忆，只上传其判断会影响生成结果且适合保存的原始片段。
- 使用者不逐条预览或确认记忆材料；记忆筛选是本地 Agent 的职责，不增加老师操作步骤。
- 不上传完整聊天、系统提示、私有推理、工具参数或结果、Checkpoint、凭证、本地主机路径、其他任务或其他用户内容。
- 不上传仅被认为“可能相关”但本轮没有实际加载的记忆，也不上传其他任务、其他用户、凭证、系统控制指令或记忆库索引。
- 同一参考样例或记忆材料用于多道题时，每道题独立保存；修改或删除一题不能影响其他题。

## Skill workflow

- Skill 只在用户明确要求沉淀或上传评测题时执行真实上传。
- Skill 从当前可见上下文识别 `0..N` 道候选题；看不到被压缩或不可访问的历史时必须说明边界。
- 新的、可独立完成并独立评测的任务要求形成新题。
- 同一任务下的初稿、否定、修改和重写归入同一道题，形成多个 Bad case 与反馈。
- 某题缺少标准答案时，Skill 逐题询问老师补充或确认；不能自行把最后一次 Agent 输出当作标准答案。
- Skill 展示用例标题、题目、参考样例、Bad case/反馈和标准答案的整批预览。老师可以修改内容、删除候选题和调整题目边界；记忆材料由 Agent 自动筛选，不要求使用者预览。
- 每道候选题同时展示本地 Agent 生成的简短用例标题，老师可以在整批预览中修改；该标题仅为检索元数据。
- 只有所有保留题目的可见材料边界和标准答案均已确认，且 Agent 已完成记忆材料筛选，才允许批量上传。
- Skill 从本机私密配置读取 API 地址和场景凭证；明文凭证不得写入仓库、Skill、日志或 payload。

## Batch upload

- 外部 API 一次接收 `0..N` 道题，每道题有稳定 `client_case_id`，整批有稳定 `command_id`。
- 场景由凭证决定，Skill 不能提交或覆盖场景 ID。
- 批量入库采用事务级全成全败：整批校验通过后，才写入所有题目、六类材料、评分生成任务和幂等回执；任一题失败则全部不创建。
- 相同 `command_id` 和相同 payload 重试返回同一结果；内容改变后必须使用新命令。
- Skill 中的总体确认代表使用者可见材料已经确认，记忆材料则由 Agent 自动筛选。上传成功后，后端立即为每道题排队生成评分维度，不再要求平台内重复确认或手动开始生成。
- 提交后每道题的 AI 任务独立运行；单题生成失败不删除题目，也不影响同批其他题，且支持安全重试。

## Score dimension model

- 平台 AI 仅根据题目自身六类材料生成 `1..N` 个评分维度，不读取场景名称或场景配置。
- 每个维度仅包含：
  - `name`：字符串；
  - `description`：字符串；
  - `pass_score`：整数。
- 三项初始建议均由 AI 生成，管理员可以新增、删除和修改。
- 每个维度固定满分 10 分；`pass_score` 范围为 `0..10`。
- 每个维度都必须达到自己的及格分；任意一项不及格，整题不通过，其他维度高分不能补偿。
- 不保留权重、自定义满分、给分点列表、扣分点列表、关键项模式、标准答案预期得分、预期理由或全局及格线。

## Editing and publication

- Skill 上传后，题目状态为评分维度生成中、生成失败可重试或维度待确认。
- 管理员可以在发布前后直接修改六类材料。
- 材料编辑只有一个提交动作：“保存并重新生成”。它覆盖当前材料、使旧维度失效并创建新一轮生成任务。
- 不在字段输入过程中调用 AI，也不提供会留下“新材料 + 旧维度”的独立保存动作。
- 评分维度生成失败时保留最新材料，可幂等重试。
- 发布只将当前题目和当前评分维度标记为正式可用。
- 已发布题目再次修改时直接覆盖当前内容并回到待处理状态。
- M0 不保留题目历史版本、修订记录、旧发布内容或派生草稿。
- 后端可使用内部 revision/CAS 防止并发覆盖，但不能把它扩展为用户可见版本体系。

## Identity and administration

- M0 只有一个平台管理员，由管理员管理全部场景、题目、维度和发布。
- 业务老师不创建平台账号，也不直接登录；只通过场景绑定的 Skill 提交材料。
- 无前端过渡期提供管理员 CLI：创建场景，生成、轮换和撤销场景凭证，查询非敏感绑定状态。
- 明文凭证只在生成或轮换成功时显示一次，后续状态查询不返回。
- 场景凭证只能查询自身连接状态和批量上传题目，不能读取、修改、删除或发布题目。

## Backend/API requirements

- 提供统一题库列表 API，可按状态和场景筛选，返回题目当前状态、评分生成状态和下一步动作。
- 提供题目详情、保存并重新生成、修改评分维度、重试生成、发布和删除 API。
- 题库列表与题目详情返回独立的用例标题 `title`；单独改名不改变六类材料，也不触发评分维度重新生成。
- OpenAPI 是 Skill 和未来前端的唯一机器可读合同，并有纯后端漂移检查。
- 后端业务数据库是题目、材料、维度和状态的事实源；AI Runtime 不能直接确认或发布业务事实。

## Legacy removal

- 删除当前产品前端和只为它服务的 Node/Next.js、Playwright、生成类型与构建依赖。
- 删除旧网页手动上传原始文件、服务端解析、文件用途确认、AI 分组和共创建题链。
- 删除旧 Working Set、覆盖审查、版本包和题目修订历史链。
- 删除待评结果、人工评分和跨修订重评链。
- 删除对应 Router、Schema、Service、Repository、数据库表与数据、OperationJob 类型、AI Adapter、脚本、测试、配置、文档和变量。
- 只保留新链路实际需要的数据库基础、任务租约/重试能力和 AI Provider 接入，并去除旧业务命名。
- 不保留兼容路由、旧 DTO、旧状态、旧格式读取、双写或隐藏入口；不兼容历史业务数据。

## Out of scope

- 新正式前端的设计与实现。
- 题目跨场景移动或复制。
- 从平台取题、注入参考样例或记忆材料、执行被评 Skill、回传结果、人工评分或自动评分。
- 原文件上传、服务端解析、ZIP 解包、OCR 和附件对象存储。
- 任何题目版本追溯或历史修订。
- 未经最终规划批准的产品代码修改或 `task.py start`。

## Acceptance Criteria

- [ ] 一个统一题库包含全部待处理和已发布题目，并支持状态与场景筛选。
- [ ] 可创建多个场景文件夹并分别生成独立上传凭证；M0 不支持题目跨场景移动或复制。
- [ ] Skill 可从真实上下文识别 `0..N` 道题、补齐标准答案、展示使用者需要确认的整批预览，并自动筛选记忆材料后上传。
- [ ] 批量上传全成全败；同 payload 幂等重放，变更 payload 冲突，不产生半批数据或孤立生成任务。
- [ ] 每道题独立保存题目、参考样例、Bad case、老师反馈、标准答案和记忆材料。
- [ ] 参考样例只来自老师提供且 Agent 实际读取的内容整理；记忆材料只包含 Agent 从本轮实际加载记忆中筛选出的相关、安全原始片段，且不绑定某个 Skill。
- [ ] 上传成功后每题自动进入评分维度生成；任务可独立成功、失败和重试。
- [ ] 评分维度合同只有 `name + description + pass_score`，固定 10 分且逐项必须及格。
- [ ] 管理员可对当前六类材料执行“保存并重新生成”，并增删改维度后发布。
- [ ] 已发布题目修改后直接覆盖并回到待处理，不保留旧版本或修订历史。
- [ ] 单管理员和场景凭证权限隔离正确，凭证不会被存入源码、日志或响应历史。
- [ ] 旧前端、旧手动建题、文件处理、Working Set、版本包和人工评分语义及其代码全部删除。
- [ ] 后端可独立安装、迁移、启动、测试并生成/校验 OpenAPI，无 Node/Next.js 依赖。
- [ ] 使用 `/Users/hsikey/BenchMark/EvalData` 模拟真实上下文，验证多题识别、材料边界、缺失答案追问和批量上传；不输出源正文或秘密。

## Delivery split

1. 新题库领域模型与 API：六类材料、批量收题、自动评分维度、当前发布状态、管理员接口和破坏式迁移。
2. 旧链清理与后端工程收敛：删除旧业务能力、旧前端和 Node 依赖，重建纯后端质量门。
3. 上传 Skill：仓库内 Skill、私密配置、上下文识别、整批预览、确认上传和 EvalData 模拟验收。

三个子任务必须串行完成；前一项合并并在 `main` 复验后，才能开始下一项。
