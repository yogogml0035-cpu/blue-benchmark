# EvalData 批量收题模拟可行性

## 样本事实

`/Users/hsikey/BenchMark/EvalData` 当前有三份顶层输入：

- 完整 Markdown 对话导出：约 612 KB、10,254 行；
- 原始 JSONL：约 737 KB、310 条事件，其中包含大量 user、assistant、attachment、工具和状态事件；
- ZIP：包含 3 份 Markdown 材料，展开约 265 KB。

样本包含长对话、多轮修改、老师否定反馈、多个产物阶段、附件读取、Skill 指令和记忆相关操作，适合验证“本地 Agent 已完成工作后，再调用上传 Skill”的真实输入形态。

## 可验证能力

- 从大量系统/工具噪声中只提取用户可见业务材料；
- 验证本地 Agent 能从实际加载的记忆中保留相关原文、排除无关或敏感片段，且不要求使用者逐条审阅记忆；
- 识别 `0..N` 道候选评测用例；
- 为每道题隔离题目、参考样例、记忆材料、Bad case/反馈和标准答案；
- 检出绝对路径、工具参数、Skill 列表、系统提示和其他不可上传内容；
- 展示整批预览，允许逐题删除或修改；
- 总体确认后执行批量 API 上传；
- 验证幂等重放和逐题响应映射。
- 构造其中一道题无效的批次，验证整批无题目、无材料、无生成任务、无完成回执；修正后用新命令完整上传。
- 构造两道题使用相同参考样例或记忆材料的批次，验证各自形成独立业务内容；修改或删除一题不影响另一题，底层即使去重也不能共享可变记录。

## 不能预先假定

长上下文包含多个修改阶段，并不自动意味着存在多道题。题目切分规则已经确认：新的独立任务要求形成新题；同一个任务要求下的初稿、反馈和终稿仍是同一道题的多个证据。不能用消息轮次、文件数量或改稿次数机械切分。

若某个独立任务在样本上下文中没有老师认可的最终结果，模拟 Skill 必须将它标记为缺少标准答案并发起逐题追问；不得把最后一条 Agent 输出自动视为标准答案。

## 测试边界

- 原始 EvalData 不复制进仓库。
- 默认测试输出只记录题目数量、阶段、ID 和错误类型，不打印正文、记忆、路径或凭证。
- 规划阶段只做只读结构分析；真实上传必须等实施批准并使用隔离场景与可撤销凭证。
