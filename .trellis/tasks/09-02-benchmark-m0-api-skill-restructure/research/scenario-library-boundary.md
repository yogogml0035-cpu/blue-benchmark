# 场景与题库边界

## 产品结论

- 平台只有一个统一题库，包含所有场景下的待处理和已发布题目。
- 场景只是统一题库中的文件夹；可用于筛选和上传凭证归属，不形成独立题库产品。
- 用户不需要进入两个模块寻找“草稿”和“正式题”；状态标签、筛选和下一步动作负责区分。

## 数据设计结论

产品上的统一题库不强制数据库使用一张宽表，但每道题只有一份当前业务记录。AI 评分维度生成任务和幂等回执可由独立记录持有；后端通过统一查询 DTO 返回用户看到的题库列表。

这样同时满足：

- 使用者只理解一个题库；
- 未完成题目不会冒充正式发布状态；
- 已发布题目修改后直接覆盖当前内容并回到待处理，不保留历史版本；
- 前端不需要理解数据库表结构。

## 风险

若只依赖一个 `status` 字符串而不返回明确 `next_action`，未来前端会重复实现状态判断。聚合 API 应同时返回稳定状态、评分维度生成状态和管理员下一步动作。
