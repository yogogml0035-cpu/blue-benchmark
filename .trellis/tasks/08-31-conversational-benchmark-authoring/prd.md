# Benchmark 收题、发布与人工评分重构

## Goal

让业务老师把真实 Agent 工作中的任务要求、相关文本输入、坏样本和标准答案沉淀为账号私有场景中的正式评测用例，并在平台内生成和确认评分规则、自动留下不可变评测集历史；同时保留对外部待评结果的独立人工评分能力。

## User Value

- 老师不需要手工导出整段对话再上传，也不需要理解 JSON、场景合同、组集草稿或冻结流程。
- 本地 Agent 可以通过稳定 API 创建完整待确认草稿，老师只在平台审阅 rubric 并发布。
- 发布、修改、停用、恢复和删除自动维护当前评测集及历史版本，过去的用例、待评结果和评分可回查。
- 平台不绑定某个 Skill 名称或执行环境；同一 Benchmark 可以被未来不同 Skill 或 Agent 复用。

## Current Implemented Facts

- `main` 已实现全中文可恢复建题会话、单题输入与一份标准答案确认、安全流式业务投影和不可变题目修订。
- `main` 已实现 100 分 rubric、标准答案逐项锚点、关键最低分/一票否决、老师确认与发布。
- `main` 已实现平台外单份文本/Markdown 待评结果提交、服务端确定性人工评分、不可覆盖历史和同修订 parent-linked 重评；当前源码用户文案需要统一迁移为“待评结果”。
- 当前 Workspace 已按 `owner_user_id` 隔离；浏览器 API 使用 HttpOnly Session Cookie，外部 Agent 尚无专用凭证。
- 当前仍保留强制场景合同、手动 WorkingSetDraft/组集/freeze 和版本包流程；发布题目不会自动进入正式评测集。
- 当前人工评分不能让同一待评结果按另一条已发布题目修订重评。
- 当前题目只保存一份标准答案，尚未保存带否定原因的坏样本。
- 现有 `EvaluationSetVersion` 与 `runtime / judge / provenance` 不可变版本包已经具备历史读取和泄漏隔离基础。

## Confirmed Product Decisions

### Product boundary

- 当前 M0 以题目收录、rubric 发布、自动评测集历史和已完成的人工评分为边界。
- 从平台取题、调用目标 Skill、自动做题、回传运行结果和自动评分属于后续 M1，不在本轮开发。
- 已完成的人工评分无需重新归类或推倒重写，只补跨修订重评和题目生命周期门禁。

### Scene and Skill

- 场景是账号私有的 Benchmark 容器，只要求自由名称和“主要解决什么问题”的描述。
- “一个场景通常服务一个 Skill”是培训建议，不是产品约束；不要求 Skill 名称、ID、版本或一对一绑定。
- 老师把题提交到哪个场景即代表归属决定，M0 不做语义匹配、覆盖门或场景级共同标准。

### Question package

- 一次本地 Skill 调用只形成并上传一个评测用例草稿。
- 本地 Agent 负责概括题目标题，整理老师的任务要求、相关输入文件内容、坏样本及否定原因和标准答案，并在上传前展示完整预览。
- 任务要求逐字保存老师当时输入给本地 Agent 的原始提示词；Agent 和平台都不能改写。依赖前文时，把必要上下文放入输入文件内容或继续追问。
- 标准答案逐字保存老师最终认可的完整结果；Agent 和平台不得摘要、润色或重新生成。
- 所选输入文件默认逐字上传完整原文；只使用部分内容时必须创建老师确认、明确标注来源的节选输入，不能静默摘要或截断。
- 缺少明确任务要求或老师认可的标准答案时必须留在本地继续追问，不能向平台创建半成品。
- 外部 API 不再重新提炼题目，只做确定性校验、保存草稿并返回链接；不自动启动 rubric 或任何平台 AI。
- 外部草稿进入网站后可完整编辑，编辑推进普通 draft revision；`ai-eval-push` 不能读取或修改已上传草稿。
- 网站编辑完成后通过一个“确认题目并生成打分规则”业务动作进入 rubric 流程；不再保留两次用户确认。
- 一个评测用例固定由题目标题、任务要求、相关输入文件内容、一份标准答案和 0..N 份老师明确否定的坏样本组成；每份坏样本必须有确认过的否定原因。
- 坏样本只能来自当前真实 Agent 执行中实际产生并被老师否定的结果；Skill 不得合成或补造。
- 坏样本只保存老师可见结果正文和否定依据，不保存 system/tool/private trace 或绝对路径。
- 每份坏样本保存老师否定原话和老师确认的结构化原因摘要；原话逐字保留，过于笼统时继续追问或放弃该坏样本，摘要不能替代原话。
- 任务要求、输入文件内容、标准答案、坏样本和原因只支持 UTF-8 纯文本或 Markdown。
- 非文本原始资料只能在本地转换为 Markdown 并经老师确认；原文件不进入平台。

### Publish and history

- rubric 审阅完成后只执行一次“确认规则并发布到评测集”；不保留新流程的 confirmed-but-unpublished 状态。
- 发布即进入场景当前正式评测集，并原子创建不可变题目修订和历史版本。
- 系统自动形成连续不可变评测集版本，不要求老师组集、创建下一版草稿或再次冻结。
- 修改已发布用例只派生唯一一个下一修订草稿，旧 revision 继续生效；只有新草稿完整发布后才原子替换并形成新版本。
- 停用、恢复和删除都自动形成新版本；停用保留未发布修改草稿但禁止发布，删除使其不可恢复。
- 停用与删除都从当前集合移除；停用可恢复，删除不可恢复。
- 普通删除不抹除历史版本、旧题目修订、待评结果和评分；历史标记该用例后来已删除。

### External authoring and tenant isolation

- 平台负责稳定上传 API；各 Agent 可以据此实现自己的适配 Skill。
- 当前适配 Skill 名称固定为 `ai-eval-push`，源码位于独立仓库 `/Users/hsikey/BenchMark/BenchMark/ai-eval-push`。
- 老师从平台目标场景发起一次绑定；凭证固定绑定当前账号和场景，切换场景需显式重新绑定。
- 场景绑定凭证不设固定自动过期时间；主动撤销、重新绑定、Workspace 删除或账号失效会立即使其失效。
- 外部凭证只能创建草稿，不能列出其他场景、读取 judge/provenance、发布、删除或评分。
- `ai-eval-push` 上传后立即返回新草稿链接并结束；老师点击网站链接后才生成 rubric、确认和发布。
- `ai-eval-push` 只显式触发；连接凭证安全存储，不进入源码、`.env`、命令回显或 Git。
- 返回链接必须定位到绑定场景下的精确可编辑草稿，而不是场景首页或只读页面。
- API 完成后构建、真实 E2E、全局安装 `ai-eval-push`，再通过已授权 `gh` 创建私有仓库 `yogogml0035-cpu/ai-eval-push` 并推送。

## Requirements

### R1. Keep completed authoring and scoring stable

- 已完成的建题、rubric 和人工评分合同保持可用；新迁移不删除旧数据或静默改写历史。
- 网站手动与外部创建的草稿统一采用“确认题目并生成打分规则”组合命令；生成失败只重试规则，重新编辑则使确认失效。
- rubric 草稿统一采用“确认规则并发布到评测集”组合命令；失败保持规则审阅态，不留下半发布状态。
- 人工评分继续绑定不可变待评结果和每次实际使用的不可变题目修订；服务端推导分数和通过结论。
- 所有业务写入继续由 FastAPI Service/PostgreSQL 权威控制，AI 只能提出候选。

### R2. Cross-revision rescoring

- 同一份不可变待评结果的首次评分使用原题目修订；后续重评只可选择相同 `question_draft_id` 下的其他已发布修订。
- 每条评分独立保存所用修订，历史必须按各自修订还原评分项和结论。
- 不复制正文，不覆盖旧评分，不允许跨 Workspace 或跨逻辑用例串线；另一个用例必须创建新的待评结果记录。

### R3. Simplified lifecycle

- 新建题、发布和自动版本不再依赖强制场景合同。
- 发布/修改/停用/恢复/删除与自动版本必须具备原子性、幂等和并发保护。
- 停用/删除用例不接受新的待评结果或任何新增评分/重评，但已有待评结果和历史评分继续可读；停用恢复后重新开放，删除永久只读。
- 旧手动版本和旧包保持只读兼容；新 UI 不再把它们作为日常必经流程。

### R4. Bad samples

- 坏样本及否定原因进入题目修订、rubric 生成证据和 judge/provenance。
- 坏样本不得进入 runtime，不得自动变成字符串黑名单或相似度评分。
- 老师最终确认评分项、扣分点和关键项。

### R5. External authoring API

- 提供一次性连接兑换、场景绑定最小权限凭证、绑定状态、撤销和结构化单题草稿上传。
- 服务端从凭证派生账号和 Workspace，不信任客户端提交的租户 ID。
- 上传使用版本化严格 Schema、UTF-8/Markdown 限制、command 幂等、内容 hash 和安全错误合同。
- 成功同步返回绑定场景下的精确 Web 草稿链接；上传不创建 AI/rubric OperationJob。链接本身不携带授权，浏览器仍需对应账号 Session。
- 网站编辑保留最初外部上传 receipt/hash 并推进 draft revision；外部凭证没有草稿 GET/PATCH/DELETE 权限。

### R6. Privacy and visibility

- 任务要求、输入内容、标准答案、坏样本、凭证明文、系统提示、工具原文、绝对路径和 private reasoning 不进入日志、错误、SSE、Git 或其他账号响应。
- 未来做题端只能读取 runtime；标准答案、坏样本、rubric 和老师判断不可见。

## Out of Scope

- 平台内执行 Skill、模型/Agent 配置、自动考试、结果回传、AI Judge、批量评分、排行榜和实验报告。
- 多成员、角色、邀请、组织级权限和复杂协作。
- PDF、Word、Excel、图片、音视频、ZIP、代码工程作为题目输入或答案的在线解析/保存。
- 场景级 Skill 身份、强制覆盖率和共同硬门禁。
- 彻底擦除历史数据的合规清除流程。
