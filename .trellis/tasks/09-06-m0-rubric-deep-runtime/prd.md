# C2：Deep Agents 持久运行基础

## 状态与依赖

- 状态：planning。父任务：.trellis/tasks/09-05-m0-rubric-anchors-evidence；本轮没有实施批准。
- 必须等待 C1（09-06-m0-rubric-real-samples）交付并合入已复验的 main，再创建本任务实施 worktree。
- 本任务交付可复用且经过验证的运行能力；不启用生产评分入口、不改变题目或删除 API。

## 目标

验证并提供最新 Deep Agents 的受限执行、真实流式、同线程持久化/恢复与清理能力，让 C3 可以一次性接入已验证的运行基础。

## 范围

- 实时核查最新正式 SDK 并锁定依赖，验证当前模型/relay 的工具调用、增量流和结构化结果，不沿用过期示例。
- 受限材料读工具、线程内工作文件、公开事件归一、调用预算和必要 middleware；不开放 shell/web/宿主机任意文件或跨题记忆。
- 在同一 Docker 实例的本任务独占 checkpoint 测试库验证 PostgreSQL Saver、StateBackend、加密、连接生命周期、单写者和完整线程删除。
- 独立验证 interrupt/回复后恢复协议，但不发布 M1 询问、聊天或评分入口。
- 不新增业务消息表/题目状态，不绑定生产 RubricGenerator，不将底层验证成功称为整个平台接入完成。

## 验收标准

- 最新正式依赖与实际 API 合同有本次证据；技能中不适用的 StateBackend(runtime)、harness_profile 等写法不得照抄。
- 使用 C1 重建的真实材料，真实 Provider 能完成受限工具、流式和结构化结果探针；缺配置/失败明确报告，不用 stub 冒充真实探针。
- 同一 thread 重启后恢复消息/工作文件，不重复初始输入；不同 thread 隔离，未完成模型调用可能重试但过程明确标识。
- 检查点删除覆盖相关 namespaces、writes、blobs 与工作文件；不清其他线程或现有项目旧测试库。
- 锁/连接失败、同线程双写、中断透传、middleware 顺序与状态更新有定向测试；清理原语不依赖模型可用性。
- 现有产品的 API、前端和默认生成路径仍按基线工作；新组件只有底层接口与显式测试探针，没有第二个生产入口或兼容开关。

## 交接

- C3 消费已合入 main 的运行组件、接口说明和验证记录；业务映射、消息落库、队列接入与 UI 展示仍由 C3 完成。
- 后续执行与交付时继续检查最新正式版本；版本变化需重新验证，不能把本次锁定误作永久版本目标。
