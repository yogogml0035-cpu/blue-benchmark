# Technical Design

Skill 采用简短 `SKILL.md` + 确定性 Python 客户端脚本 + API 合同 reference。Agent 负责从当前上下文组织候选和向老师确认；脚本只负责读取配置、严格校验 JSON、生成或复用 `command_id`、执行 HTTP 请求和归一化错误。

本机配置优先从 `AI_EVAL_BASE_URL`、`AI_EVAL_ACCESS_TOKEN` 环境变量读取；可选用户级配置文件必须位于仓库之外并要求安全权限。仓库只提供无秘密示例。

真实上传前，Agent 必须展示 `0..N` 道候选题中需要使用者确认的题目、参考样例、Bad case/反馈、标准答案和辅助名称，并获得当轮总体确认。记忆材料不展示逐条原文供使用者审阅。老师仍可逐题修改、删除或调整题目边界。脚本不接收 workspace ID；场景只能由 Bearer token 决定。

记忆材料由本地 Agent 从本次任务实际加载并进入上下文的记忆中筛选：只保留与当前题目有关且适合上传的原始片段，保存可选安全来源标签，不生成摘要。来源可以是业务 Skill、用户、本地项目或其他记忆机制，不建立 Skill 绑定。确定性脚本再执行路径、凭证和受限字段扫描，拒绝明显泄漏；它不承担语义相关性判断。

每道题使用稳定 `client_case_id`，整批使用稳定 `command_id`。脚本一次发送批量请求并显示逐题创建结果，不在客户端用多个无关联请求伪造批量语义。

批量接口为原子操作。失败响应应定位 `client_case_id` 和字段，但不创建任何题；Skill 保留本地预览，老师修正后使用新的批次命令重传。成功响应按输入顺序返回全部映射。

成功上传后，每道题已由服务端排队生成评分维度。Skill 只报告逐题的草稿 ID 和初始生成状态，不轮询到 AI 完成，也不代替平台进行规则审阅或发布。

候选切分规则：新的独立任务要求形成新题；同一任务下的初稿、被否定结果、老师反馈和后续重写继续属于同一题。若某题没有老师认可的标准答案，Skill 在批量预览前逐题追问补齐。

同一参考样例或记忆材料属于多道题时，Skill 为每道题生成独立材料项和稳定客户端 ID。服务端可用哈希优化存储，但 Skill 不发送可变的跨题共享对象引用。

参考样例发现以当前 Agent 可见上下文为依据：只纳入老师本次提供且 Agent 实际读取过的文件、附件、数据或内容，并整理为与当前题目有关、来源可支持的文本。绝对路径、文件本体和内部读取元数据不能进入预览 payload 或平台响应。

题目不携带业务 Skill 身份字段；记忆材料作为独立的上下文/背景资料上传。
