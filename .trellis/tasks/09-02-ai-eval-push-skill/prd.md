# 构建场景绑定的评测用例上传 Skill

## Goal

在仓库 `skills/ai-eval-push/` 中提供可复用 Skill：从本地 Agent 当前可见上下文识别 `0..N` 道题并分别整理六类材料，经老师总体确认整批预览后，用场景限定凭证调用平台 API 创建待处理评测题。

## Requirements

- Skill 只在用户明确要求沉淀/上传评测用例时执行真实上传。
- 从环境变量或用户级私密配置读取 API 地址和场景凭证，不保存明文秘密。
- 自动提取候选：用例标题、题目、参考样例、Bad case、与 Bad case 绑定的老师反馈、标准答案、记忆材料。
- 本地 Agent 为每道候选题生成简短用例标题，老师可在整批预览中修改；标题只用于题库检索，不属于六类材料。
- 参考样例候选来自老师本次提供、且 Agent 在当前可见上下文中确实读取过的文件、附件、数据或内容；Agent 可以整理为与当前题目有关的文本，但不得扫描未读取材料、添加无来源事实或上传原文件。
- 一次调用可以产生多道候选题；预览中每道题材料隔离，老师可逐题修改或删除后一次总体确认。
- 同一参考样例或记忆材料用于多道题时，Skill 在每道题的预览和 payload 中分别明确列出，不能用批次级共享引用隐藏题目边界。
- 新的独立任务要求形成新题；同一任务的多轮生成、否定和重写归入同一道题。
- 每道候选题必须有独立标准答案；上下文缺失时，Skill 逐题询问老师提供或确认，不能自行补造。
- 题目、记忆材料原文、反馈原话和标准答案不得被静默改写或截断；参考样例允许整理，但必须保持来源支持并经老师确认。
- 本地 Agent 从本次任务实际加载并进入上下文的记忆中，自动判断并保留与当前题目有关、适合上传的原始片段；无关或敏感片段不得进入 payload。
- 记忆来源可以是业务 Skill、用户、本地项目或其他记忆机制，不要求绑定或识别某个 Skill。
- 不得收集本轮未实际加载的记忆、其他任务或其他用户内容、凭证、系统控制指令和记忆库索引。
- 上传前展示除记忆原文外的结构化整批预览并取得明确确认；记忆材料不要求使用者逐条预览，缺少标准答案或关键来源时继续追问。
- 老师总体确认后，上传即代表使用者可见材料已确认，记忆材料由 Agent 负责筛选；平台自动为每道题排队生成评分维度，Skill 不再要求老师去平台重复确认材料或手动点击生成。
- 使用稳定 `command_id` 支持安全重试；认证、撤销、限流、校验和网络错误给出可操作反馈。
- 批量上传必须全部成功或全部失败；失败时保留本地整批预览供老师修正，不把部分成功误报为完成。
- Skill 不读取或管理已上传题目，不生成规则，不发布，不跨场景指定 scene/workspace。

## Acceptance Criteria

- [ ] Skill 目录通过官方快速校验，无占位内容。
- [ ] 确定性脚本能校验六类材料并调用连接状态/上传接口。
- [ ] 配置缺失、凭证无效、重复上传、payload 无效和成功均有测试。
- [ ] 记忆筛选测试覆盖相关片段保留、无关/敏感片段排除、原文不改写，以及使用者不需要逐条预览记忆。
- [ ] 任一候选题无效时整批不创建，Skill 能定位失败题与字段并保留待修正预览。
- [ ] 使用 EvalData 模拟本地 Agent 上下文，完成多题识别、总体确认后的真实批量 API 联调；数据库/API 回读逐题一致且不输出秘密或正文。
- [ ] 批量上传响应能显示每题已入库且评分维度处于排队/生成状态，真实 AI 失败时提供逐题可重试信息。
- [ ] 模拟测试证明同一任务的多轮修改不会误拆成多题，新的独立任务要求会形成新题，缺失标准答案会触发逐题追问。
- [ ] EvalData 模拟能识别实际读取的 Markdown、JSONL 与 ZIP 内材料，并排除仅出现路径、工具元数据或未读取文件。
