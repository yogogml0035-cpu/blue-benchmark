# Benchmark 外部收题 API

## Goal

让本地 Agent 在老师明确确认后，把一份完整、结构化、文本型评测用例草稿安全写入已绑定场景，并返回平台草稿链接；平台仍是账号隔离、rubric 生成、发布和历史的唯一权威。

## Dependency

- 本任务依赖 `benchmark-question-lifecycle-simplification` 完成并合并，因为外部 API 必须绑定稳定的场景、题目和发布生命周期合同。
- API 合并并完成 E2E 后，才在独立仓库 `/Users/hsikey/BenchMark/BenchMark/ai-eval-push` 创建客户端 Skill。

## Confirmed Product Decisions

- 平台暴露稳定核心 API；Codex、Claude Code 或其他 Agent 可以各自实现适配 Skill。
- 当前交付的适配 Skill 名称固定为 `ai-eval-push`，但其代码不属于平台仓库。
- 一次 Skill 调用只创建一个评测用例草稿。
- 本地 Agent 负责概括题目标题，整理老师的任务要求、相关输入文件内容、坏样本及否定原因和标准答案，并在上传前展示完整预览。
- `task_requirement` 必须逐字保存老师当时输入给本地 Agent 的原始提示词；本地 Agent 和平台都不能摘要、润色、补写或改写。
- `reference_answer_text` 必须逐字保存老师最终认可的完整结果；不能由 Skill 摘要、润色或重新生成。
- 若原始提示词依赖前文，Skill 必须把必要前文作为输入文件内容纳入预览，或继续追问老师补齐；不得把隐含上下文静默改写进任务要求。
- Skill 负责选择与任务相关的输入文件；一旦选中，默认上传该 `.txt` / `.md` 文件的逐字完整原文，不能摘要、截断或省略。
- 若老师只使用文件的一部分，Skill 必须创建并明确标注一份“老师确认的节选输入”，展示来源文件与节选内容；不能冒充完整原文件。
- 缺少明确任务要求或老师认可的标准答案时，本地 Agent 必须继续追问并阻止上传。
- 外部 API 只做确定性校验并保存评测用例草稿，不启动平台 AI、不生成 rubric、不确认、不发布。
- 成功后返回绑定场景下这道新草稿的精确 Web 链接；老师点击链接后才在网站继续题目与 rubric 流程。
- 外部创建的草稿与网站手动创建的草稿采用同一编辑合同；老师可在网站修改题目标题、任务要求、输入文件内容、标准答案、坏样本和否定原因。
- `ai-eval-push` 及其凭证不能读取或更新已创建草稿；修改只发生在浏览器 Session 鉴权的网站中。
- 网站编辑完成后使用一个“确认题目并生成打分规则”动作；rubric 审阅后使用一个“确认规则并发布到评测集”动作。这两个动作都不属于外部 API 或 Skill。
- 场景通过一次绑定确定；老师不在每次上传时记忆或选择账号/场景。

## Requirements

### R1. 场景绑定

- 老师在已登录平台的目标场景中发起“连接本地 Agent”，获取短时有效、一次性使用的连接信息。
- 连接交换后得到只绑定当前账号和当前 Workspace 的可撤销凭证。
- 外部上传请求不得接受或信任客户端提交的 `account_id` / `workspace_id`；服务端从凭证派生归属。
- 凭证至少只允许读取绑定场景显示信息和创建评测用例草稿，不能读取其他场景、历史用例、标准答案、rubric 或待评结果。
- 切换场景必须显式重新绑定；重新绑定会立即撤销这一本地连接的旧凭证。

### R2. 凭证安全

- 一次性连接码短时有效、单次兑换、不可从数据库或日志还原。
- 长期连接凭证只以安全 hash/受保护形式保存，明文不进入数据库、日志、错误、事件、URL 查询参数或 Git。
- 长期连接凭证不设固定自动过期时间，持续有效到老师主动撤销、重新绑定、Workspace 删除或账号失效。
- 凭证有创建时间、最后使用时间、撤销时间/原因和明确 scope；泄漏影响限制在一个 Workspace 的 draft:create。
- Workspace 改名不改变绑定，Skill 每次预览从服务端读取当前场景名；删除 Workspace 才使连接失效。
- 草稿返回链接不是 bearer secret，打开后仍需对应账号的浏览器 Session。

### R3. 结构化单个评测用例草稿

- 上传 payload 只承载 `schema_version`、`command_id`、AI 概括的题目标题、老师的任务要求、0..N 份相关文本/Markdown 输入文件内容、0..N 份坏样本及两层否定依据和一份标准答案。
- 题目标题、任务要求和标准答案必填；坏样本可选，但每份坏样本必须保存 1..N 条老师原话 `teacher_feedback_texts`，以及一份经老师预览确认的结构化 `reason_summary`。
- `input_files[]` 的 `content_mode` 只能是 `full` 或 `teacher_confirmed_excerpt`；`full` 必须是所选文件完整原文，`excerpt` 必须保存来源文件名和明确节选标记。
- 坏样本只能来自当前真实 Agent 执行中实际产生并被老师明确否定的结果；Skill 不得合成、扩写或补造坏样本。
- 坏样本只保存老师可见的结果正文，不包含 system prompt、Skill 指令全文、工具调用参数/返回、private reasoning 或本地绝对路径。
- 老师反馈原话逐字保存，Agent不能改写；`reason_summary` 只是可编辑候选，不能替代原话。若原话只有“这个不行”等不足以解释问题的表述，Skill必须继续追问，并把老师补充回答也逐字加入 `teacher_feedback_texts` 后才能上传该坏样本。
- `task_requirement` 按原始 UTF-8 code points 保存，不能 trim、折叠空白、统一标点或替换 Skill 调用语句；canonical payload hash 覆盖原文。
- 所有内容必须是 UTF-8 文本/Markdown；不接受 PDF、Word、Excel、图片、音视频、ZIP、代码仓库或宿主绝对路径。
- 平台只验证结构、大小、编码、重复 ID、归属和内容安全边界，不重新概括标题、改写任务要求或选择标准答案。
- 成功后只创建待老师查看的评测用例草稿，不创建 `OperationJob`、rubric 草稿、题目修订或评测集版本。
- 草稿创建后进入网站可编辑状态；网站修改推进 draft revision，最初外部上传的 canonical payload hash 保留在形成记录中。

### R4. 确认与可见反馈

- Skill 必须在发请求前向老师展示目标账号/场景、题目标题、任务要求、输入文件内容清单、坏样本及原因和标准答案，并获得显式确认；平台接口不能假设调用方已经安全确认，仍需完整校验。
- `ai-eval-push` 只允许显式调用，不能根据普通对话隐式触发上传流程。
- API 成功响应返回草稿 ID、`draft_ready` 语义状态、绑定场景显示名称和该草稿的同源平台链接。
- 链接必须定位到可编辑的这道草稿，而不是场景首页、列表页或只读快照。
- 未登录时链接先进入登录页，成功登录后必须回到同一草稿，不得丢失目标或跳到其他账号资源。
- 重复 `command_id + payload` 返回原草稿；同 command 不同 payload 返回 `409 COMMAND_ID_REUSED`。
- 连接失效、场景停用/删除、账号越权、Schema 不兼容和内容不完整均返回稳定机器码与安全中文说明。

### R5. 租户隔离

- 外部凭证只能写入其绑定 Workspace；猜测其他资源 ID 不得泄漏存在性或元数据。
- 外部写入按连接/token 实施请求频率、并发数和 payload 大小限制；限流不得回显正文或泄漏其他租户状态。
- 用例草稿、输入内容、错误和草稿链接不得出现在其他账号的列表或响应。
- 平台现有浏览器 Cookie 继续服务 Web UI；外部凭证不复用或导出浏览器 Session Cookie。

### R6. 客户端无关合同

- OpenAPI 是核心上传 API 的事实源；`ai-eval-push` 只消费生成或版本化合同，不复制平台业务规则。
- API 使用显式版本和兼容策略；破坏性变更必须新增版本或提供迁移期。
- 平台仓库提供 E2E 测试客户端证明合同可用，但不把 `ai-eval-push` 源码放入平台仓库。

## Out of Scope

- 从平台取题、调用目标 Skill、自动做题、提交运行结果和自动评分；这些属于后续 M1。
- 通过外部上传请求自动生成 rubric、确认用例或发布用例。
- 用外部凭证读取、修改、停用或删除已创建草稿；这些动作只通过网站 Session 执行。
- 外部客户端安装、更新和多 Agent 分发；由各客户端仓库负责。
- 创建场景、列出账号全部场景或用外部凭证读取 judge/provenance。
- 非文本资料在线解析和不完整草稿上传。

## Acceptance Criteria

- [ ] AC1：已登录老师可从一个 Workspace 创建一次性连接信息，并由客户端兑换为场景绑定的最小权限凭证。
- [ ] AC2：凭证无法列出或访问其他 Workspace，伪造 account/workspace/resource ID 不改变绑定目标。
- [ ] AC3：一次请求创建且只创建一个完整文本评测用例草稿；缺标题、缺任务要求、缺标准答案、坏样本缺老师原话/确认摘要、非文本、被静默截断的文件或未标注来源的节选被拒绝。
- [ ] AC4：所选完整文件逐字保存；老师确认的节选明确标记来源。坏样本均可追溯到当前真实执行，老师反馈逐字保存，摘要经老师确认，Skill 不能合成或用摘要覆盖原话。
- [ ] AC5：平台不重新概括标题或改写任务要求；`task_requirement` 与老师原始提示词逐字一致，保存内容与确认预览的 canonical payload/hash 一致。
- [ ] AC6：标准答案逐字等于老师最终认可结果；坏样本仅含可见结果正文与两层否定依据，不含系统/工具/private trace。
- [ ] AC7：重复请求幂等，同 command 不同 payload 冲突；并发重放只产生一份草稿，超频/超并发/超限 payload 安全拒绝。
- [ ] AC8：成功响应包含服务端当前场景名和精确可编辑草稿 URL；登录后回到同一草稿，上传不会创建 AI/rubric OperationJob 或自动确认/发布。
- [ ] AC9：老师可在网站修改外部草稿并推进 revision；原上传 hash/形成记录保留，外部凭证不能读取或更新草稿。
- [ ] AC10：凭证明文、任务要求、输入内容、坏样本和标准答案不进入日志、错误、事件或 Git；主动撤销、重新绑定、Workspace 删除或账号失效立即阻止旧凭证写入。
- [ ] AC11：OpenAPI、生成前端类型和 API E2E 一致；`make openapi`、`make test`、`make build`、`git diff --check` 通过。
- [ ] AC12：真实本地客户端可以显式完成绑定、预览后上传、断网重试和链接审阅；普通对话不隐式触发，Mock 不能冒充真实 API 验收。
