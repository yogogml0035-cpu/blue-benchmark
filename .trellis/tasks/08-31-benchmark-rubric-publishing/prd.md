# 打分规则共创与题目发布

## Goal

基于子任务一已确认的题目输入、资料边界和单一标准答案，在同一会话中生成 100 分制双层打分规则、标准答案逐项得分与理由，并由老师确认后发布为不可变题目修订。

## Requirements

### R1. 前置与隔离

- 只消费已显式确认的上游修订；未确认或已变化时拒绝生成。
- 只读取当前题相关老师反馈和证据，不串用其他题。

### R2. Rubric

- 每项包含稳定 ID、名称、目的、满分、给分点、扣分点、关键项配置、标准答案期望得分和理由。
- 满分合计 100，默认 60 分通过，可按题修改。
- 通过为总分 + 全部关键项双层判定；标准答案自身必须通过。
- 锚点不是上限，不以相似度为默认标准。

### R3. 老师审阅与发布

- Deep Agent 只提议；老师逐项编辑、确认关键项/阈值并发布。
- 发布先校验完整快照/hash，再原子创建不可变修订。
- 发布后修改创建新草稿/修订，历史版本和评分继续绑定旧修订。
- 上游变化使未发布 rubric 失效并返回子任务一。

### R4. 版本兼容

- 新题目修订可进入现有 WorkingSet/EvaluationSetVersion，但 runtime 不包含答案、规则或评分。
- v1 历史包继续按原 hash/bytes 读取，不覆盖、不重拼。

## Out of Scope

- 待评文本上传和人工评分。
- AI 自动评分、正反样本校准、Skill 执行、覆盖率/排行榜扩展。

## Acceptance Criteria

- [ ] AC1：未确认或 stale 上游不能生成/确认 rubric。
- [ ] AC2：每项字段完整、稳定 ID 唯一、满分合计精确为 100。
- [ ] AC3：标准答案有逐项得分/理由，可非满分但必须通过总分和关键项。
- [ ] AC4：待评输出可高于锚点，规则不默认比较参考答案相似度。
- [ ] AC5：老师显式确认关键项、阈值和全部规则后才能发布。
- [ ] AC6：发布失败无可见修订；重复命令幂等，并发/stale revision fail-closed。
- [ ] AC7：发布后修改创建新修订，旧修订和历史版本字节不变。
- [ ] AC8：新版本包 runtime/judge/provenance 隔离通过，v1 reader 回归通过。
- [ ] AC9：`make openapi`、`make test`、`make build`、`git diff --check` 通过。
