# 对话式题目与标准答案共创

## Goal

将聊天或手动输入通过全中文、可恢复、可安全流式展示的会话形成 0..N 道候选题，并由老师确认每道题的题目输入、资料边界和单一标准答案，为打分规则子任务提供稳定上游修订。

## Requirements

### R1. 会话与输入

- 创建 AuthoringConversation，保存老师/已验证 AI 消息和单活跃轮次状态。
- 支持聊天/资料上传与纯手动题目输入；处理中可编辑草稿/选附件但不能提交，无打断或排队。
- 上传中的指令只作不可信证据，不执行。

### R2. 候选题与资料边界

- task analyzer 提议 0..N 候选题；老师可确认、拆分、合并或舍弃。
- 每份资料确认角色/优先级，不同题证据和老师反馈严格隔离。

### R3. 题目与标准答案

- 题目输入包含任务指令、输入资料、必须包含、禁止内容和必要背景。
- 标准答案只来自老师终版/明确认可稿；缺失时一次只问一个问题，不能选最后一条 AI 回复。
- 每题只确认一份标准答案。
- 老师显式确认上游修订后本子任务完成；上游再编辑会清除确认。

### R4. 中文、安全流和恢复

- 面向老师的所有内容中文；流只含已验证回复、结构化进度和受限动作摘要。
- 不泄漏正文、路径、系统提示、原始工具数据、Checkpoint/thread ID 或私有 reasoning。
- 刷新、SSE 断线、Worker 重启、答案已保存、projection-pending 和 continuity reset 都有可恢复路径。

## Out of Scope

- 打分规则、题目发布、待评答卷和人工评分。
- 平台执行 Skill、mid-run steering、原始 token 直通、WebSocket/Redis。

## Acceptance Criteria

- [ ] AC1：上传 EvalData 或手动输入可创建并恢复同一中文会话。
- [ ] AC2：一条聊天可提出多题，老师可拆分/合并/舍弃且题间证据不串用。
- [ ] AC3：没有明确终版时 AI 暂停追问；老师可补充文字或资料后继续。
- [ ] AC4：老师可审阅并显式确认题目输入、资料角色/优先级和单一标准答案。
- [ ] AC5：确认前不能进入打分规则；上游变更清除确认并推进 revision。
- [ ] AC6：同一会话只有一个活跃轮次，绕过前端的并发提交返回 409。
- [ ] AC7：安全流断线重连且不取消 Worker；GET 快照可恢复权威状态。
- [ ] AC8：流、错误和日志扫描不含上传正文、绝对路径、凭证、内部运行标识或私有思维。
- [ ] AC9：`make openapi`、`make test`、`make build`、`git diff --check` 通过。
