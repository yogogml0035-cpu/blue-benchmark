# C5：本地数据切换与最终交付

## 状态与依赖

- 状态：planning；父任务：.trellis/tasks/09-05-m0-rubric-anchors-evidence。用户批准的是拆分，尚未开始实施或清库。
- 前置：C4（09-06-m0-rubric-system-validation）完成且已在 main 重复通过真实系统验收，C1-C3 的交付提交均包含在该 main。
- 本任务是当前项目旧两库一次性清理和实际本地部署的唯一所有者；不由其他子任务提前执行。

## 目标

在完整新链路和验收已具备的前提下，安全清理当前旧测试数据、准备新 schema 与本地运行环境，让用户能够重新上传测试。

## 范围

- 实现显式预览、目标白名单、受控备份、重置、schema/连接核验与启动说明；先在自有验收库验证工具。
- 目标仅当前本地 Docker PostgreSQL 的 skill_eval 和 skill_eval_checkpoint，不含其他库、Docker volume、角色、密钥或源样本。
- 执行前再次核对 SDK 最新正式发布及现行配置，完成当前 main 的全量复验后再进行一次性切换。
- 切换后原账号会话与场景凭证失效，按现有首次注册/凭证流程重新建立；用户题库不默认混入验收样本。
- 不新增旧数据读取转换/回填、自动 reset、跨题记忆、公网部署或新的备份产品。

## 验收标准

- dry-run 能列明脱敏目标和影响范围；目标不匹配、存在未确认共享用途或并发写入时拒绝执行，不按任意 DATABASE_URL 盲目清库。
- 重置工具先在隔离资源验证成功与失败回退，普通 make test、migration、应用启动绝不隐式触发清理。
- 当前项目旧题/维度/生成记录/checkpoint 按一次性授权清除，新 schema 和连接正常，可按新流程注册和上传。
- 六个源文件 hash 不变，不修改 .env 密钥、不清其他项目数据；备份和真实运行产物不进入 Git。
- 实际运行目录、提交、端口、API/Worker/前端和配置身份可核查；不能用另一个 worktree 的服务或 HTTP 200 冒充交付。
- main 的完整质量门、真实集成/冒烟/浏览器与恢复/删除验证均有最新证据；切换后的 schema、空库和启动检查明确记录。
- 用户可以获得实际可访问的本地 URL 与启动/失败检查说明；清理子 worktree 不得中断已交付的运行环境。

## 完成边界

- C5 的完成证据交给父任务做跨子任务最终验收；父任务须核对全部子任务和 main 证据，不能因 reset 命令成功就完成。
- 本次授权不是未来定时清理或删除新上传数据的授权；日常单题删除只按 C3 的确认门禁执行。
