# C2 统一 Harness 生产合同并完成根因修复验收

状态：已获实施批准（2026-09-08，用户批准覆盖整棵任务树）；开工仍以 C1 通过并交付已验证 main 为先决门。父任务：[统一 Harness 合同](../09-08-ai-harness-contract/prd.md)。

## 目标

在 C1 已证实目标网关能力之后，将当前评分生成一次性切换为一致的 Harness 运行合同，完成原报错根因修复、可诊断错误处理和真实业务验收。C2 完成即应满足父任务 AC1–AC8，不能把验收或旧路径删除推到后续子任务。

## 前置依赖

- C1 `09-08-ai-harness-capability` 已完成/归档、全部 C1-AC 通过，且探针与脱敏 PASS 报告的交付提交已包含在最新已验证 main。
- 人工比对 C1 模型、端点 fingerprint、effort、schema/策略和 SDK；变化时先复核能力门，不沿用失效证据。
- 已获覆盖 C2 的明确实施批准。`parent/children`、`meta.depends_on`、规划验证或上游完成本身都不是批准，也不会自动执行依赖门。

## 需求范围

本子任务承担父 R1–R7 全部生产交付：

- 显式协议配置和原生 SDK 构造；目标 Responses + medium，保留现行显式 Chat 与 Anthropic 边界。
- 同一不可变合同贯穿模型、Harness 装配、输出策略、预算与运行恢复指纹；正常生成、探针和验收共享生产入口。
- 400/配置/鉴权类错误不再自动重试；瞬时故障和内容纠正仍有界；配置在 checkpoint 之前失败也要正确终结业务作业。
- 工具/推理内部历史持久化，公开流继续过滤；协议或合同变化按现有机制重建，不转换旧消息或接受旧指纹。
- 白名单错误投影与可关联的安全诊断；保留队列、业务权威、权限、模型不可用清理和最终 CAS。
- 同任务删除旧 `_generate`、隐含 Chat 默认、分散指纹、错误默认可重试和 raw traceback 分支；接管 C1 探针，删除其临时局部模型构造，改为最终生产装配。
- 同步测试、预算生效、README/.env.example 和相关维护 spec，完整执行真实 API/Web/恢复门并在 main 复验。

## 独立验收标准

- [ ] C2-AC1：父 AC1、AC2 通过；当前模型/网关、medium、工具和完整 schema 经最终生产装配完成，C1 探针不再单独构造模型。
- [ ] C2-AC2：父 AC3、AC4 通过；本例 400 attempts=1，瞬时故障仍有限恢复，未知错误/取消不被包装成自动重试。
- [ ] C2-AC3：父 AC5 通过；真实 Worker 工具轮后恢复、不重复初始输入、完成后重提不再调用模型，合同变化与清理失败处理正确。
- [ ] C2-AC4：父 AC6、AC7 通过；安全日志能定位故障类别，权限/业务/CAS/SSE/删除等既有合同保持。
- [ ] C2-AC5：父 AC8 通过；全部旧路径和 C1 临时构造已删除，维护文档与测试同步，任务分支和同一 main SHA 的完整质量及真实系统验收通过。

详细矩阵按父 [validation-matrix](../09-08-ai-harness-contract/research/validation-matrix.md) 的 T01–T13、P01–P05、L01–L05 执行；C1 的 L01 只做开工前提，C2 仍须在最终生产入口复核，不冒充最终验收。

## 边界与风险

父任务所有不在范围项继续适用：不增加其它业务、模型路由、外部 tracing、跨题记忆或实验性流协议；不自动重试原题、修改共享库或重启现有服务。若最终生产装配暴露 C1 未覆盖的服务端不兼容，回到父设计评审，不能关闭思考或改变存储/评分项合同后自行交付。
