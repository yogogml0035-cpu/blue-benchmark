# C3：完整评分项与业务链路一次性切换

## 状态与依赖

- 状态：planning；父任务：.trellis/tasks/09-05-m0-rubric-anchors-evidence，未获实施批准。
- 前置：C1（09-06-m0-rubric-real-samples）与 C2（09-06-m0-rubric-deep-runtime）均已完成、合入 main 并复验。
- 本任务是唯一生产语义切换单元。新合同、生成接入、审改页面、流式历史与关联删除一起交付，不能拆成分别合入 main 的半套功能。

## 目标

老师能在真实题目流程中看到有依据的评分项和生成进度，自由审改并安全重生成；题目删除后不遗留平台在线生成原文。

## 完整交付范围

- 联合生成具体维度、0–10 整数通过分、少量关键分数及建议分描述、维度依据和通过分依据，区分老师明确要求与 AI 推定。
- 保留勾选/任意整数输入/全部内容编辑；普通编辑只保留并提示核对，主动整套重生成经确认后才替换，包括人工修改。
- 接入 C2 运行基础到 production Worker、业务 thread/revision 映射、完整公开消息持久化和真实流式 UI；支持回放与执行恢复。
- 实现保留原门禁的同题完整删除：历次运行过程、checkpoint/工作文件与在线副本一起清理，处理/失败可见，完成后才报成功。
- 同任务删除旧两字段完成假设、旧单次生产生成器、静态假进度、删除提前成功语义及真实验收占位兜底；维护文档与生成类型一起更新。
- 不增加 M1 新稿/实际评分/聊天入口、跨题检索/Store、旧数据兼容、独立审批或人工补造 AI 依据的发布门槛。

## 验收标准

- 初始建议分有对应表现描述；老师改成未列出的整数仍能保存，原分档/依据不被后台覆盖。
- 依据引用可核查的本题材料，定性明确要求与数字推定分开；标准答案不被另起一套外来评分流程否定。
- 新字段从生成到存储、API、前端、编辑保存及再次读取完整保留；取消重生成不写数据，确认只启动一次替换。
- 实际生成未完成时浏览器已收到公开增量；完整原文回放、同线程恢复、重复输入和过期运行防护成立。
- 删除原权限/revision/状态/标题门禁不变；同题全部历次运行在线内容清除，失败可恢复，不影响兄弟题或原始样本。
- 两组 C1 真实来源各至少一个 case 通过 production Worker + PostgreSQL + 浏览器的最小闭环，并验证一次真实恢复/完整删除；不能等 C4 才做基础验收。
- 所有受影响旧入口/DTO/测试假设同步切换，make test/build 和适用 E2E 通过；不借兼容层维持半完成状态。

## 部署边界

- 只在隔离 PostgreSQL 验收库验证新合同；当前项目旧两库的一次性清理归 C5。
- main 合入代码不等于旧演示数据库已升级。未完成 C5 前不把旧数据接入新代码，不自动 reload/发布旧演示环境，不增加读取旧数据的兜底。
- 本任务完成交付可验收的新产品链路；C4 负责扩展系统回归，C5 负责本地部署切换。
