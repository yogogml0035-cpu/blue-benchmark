# C3 设计：一次性跨层合同切换

## 权威设计与所有权

- 完整合同继承 .trellis/tasks/09-05-m0-rubric-anchors-evidence/design.md，运行与删除细节继承 .trellis/tasks/09-05-m0-rubric-anchors-evidence/runtime-design.md。
- C1 提供真实输入/预期重建，C2 提供已验证运行组件；本任务负责业务连接，不再复制另一个 runtime 或另写一套队列。
- 实施边界为 question_library、ai_runtime 接入、operations、数据库 schema、OpenAPI/TS、题目页面/编辑器与受影响验收入口。

## 数据和生成

- 统一扩展 RubricGenerationResult、业务存储、读写 DTO、fake fixtures 与前端 draft；只存在一个完整评分项合同。
- 生成校验要求稀疏锚点包含所建议整数，但编辑 DTO 不得使用锚点白名单；人工新建空辅助内容用新合同显式表示。
- 双依据保存真实来源定位、片段及主张分类；解释分数与当前通过分不同可提示，不静默改写或把 AI 推定重标老师原话。
- 服务登记 immutable 材料 revision、运行身份和 thread；Agent 只读本题材料并返回完整候选，校验通过后由服务/CAS 原子保存。
- 计入模型、工具、摘要、SDK/job 重试的全作业预算；失租、删除冻结或 revision 变化停止后续调用和写入。

## 消息、恢复与 UI

- 公开消息先落业务库再发送；checkpoint 保存执行上下文，不代替逐段消息日志。统一事件/序列与 Pydantic -> OpenAPI -> TS 合同。
- 同源 SSE 展示真实阶段和允许公开的文本；不展示私有思考、原始敏感工具输出或未经验证的 JSON 碎片。
- 浏览器重连只恢复游标；Worker 恢复同一 thread；完成图但未提交业务时复用结果补提交；确认重生成创建新 thread。
- 生成结束后仍由老师勾选、编辑与确认。沿用现有页面风格和组件，分档/依据按需展开，不改成选档控件或营销式大卡片。

## 可靠删除

- 原 DELETE 确认字段和门禁保留，新增稳定命令与删除 operation 的受理/状态合同，替换当前立即 204 即成功语义。
- 原子冻结同题并登记清理意图；复用独立 kind/target 的 OperationJob，先清全部历史 thread，再原子删除业务原文/生成历史并提交完成。
- 删除控制作业只留无原文 ID/状态，不能被生成历史清理删掉；所有编辑、生成、resume 和回放路径识别冻结。
- Worker 初始化及错误投影按实际任务职责划分，清理不依赖 Provider 可用性，不被误标为生成失败。
- 完整清理成功前显示处理/失败/重试，成功后清理受管理前端缓存；仅有 404 或页面跳转不是删除完成证据。

## 一次性删除旧语义

- 删除被替代 ModelRubricGenerator 单次生产调用、仅 criterion/pass_score 完成假设、缺字段默认填充与旧 DTO 转换。
- 更新旧静态生成轮询、提前删除跳转、验证脚本两字段断言和占位样例成功路径；保留正常详情读取、通用测试模式与仍有用途的字段。
- 现有真实验收 runner 在此接入 C1 样本、新合同和隔离 PostgreSQL；C4 不承担清除本任务应删除的旧入口。
- 更新 README、Makefile 相关入口及维护规格；已归档 Trellis 历史不批量重写。

## 发布与回退

- 产品新语义在本任务内完整可用且经过核心验收后才合入 main，不以 mock-only 前端或后台未接入状态交付。
- 不对当前旧测试库执行 schema 变更、转换或清空；实际环境切换按 C5 处理，旧演示进程与新代码明确隔离。
- 回退依 Git/受控备份/部署回退，不创建旧新双跑开关。
