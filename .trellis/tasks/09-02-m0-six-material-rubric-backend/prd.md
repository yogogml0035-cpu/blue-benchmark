# M0 六类材料与三字段评分后端

## Goal

把现有后端领域合同替换为最新 M0 模型：评测用例保存六类材料，评分维度只包含 `name`、`description`、`pass_score`，每项固定 10 分且必须分别及格。

## Requirements

- 外部收题、草稿读取/编辑、题目确认和发布快照支持 `memory_materials[]`。
- 记忆材料只保存本次任务实际读取且经老师确认的原始片段、安全来源标签和可选摘要；禁止主机路径、凭证、内部 Agent 状态和其他用户内容。
- Rubric AI 基于六类材料生成 `1..N` 个三字段维度初稿。
- 老师可增删改三字段维度；空维度、重复 ID、空泛或不安全文本、越界分数均拒绝。
- 每项固定满分 10，`pass_score` 为整数 `0..10`。
- 人工评分每项 `0..10`；任一项低于本项门槛则整题不通过。
- 总分按各项得分占总满分比例换算到 100，仅用于展示。
- 发布历史、版本包和评分历史保存新合同，不保留旧 Rubric 兼容分支。

## Acceptance Criteria

- [ ] 新外部收题 payload 能保存、读取、编辑并发布记忆材料。
- [ ] 无记忆材料是合法状态；跨用户、路径、凭证和私有运行信息被拒绝。
- [ ] OpenAPI 只暴露三字段评分维度，不再包含旧复杂 Rubric 字段。
- [ ] AI Fake 与生产结构化输出均使用六类材料和三字段维度。
- [ ] 每项必须及格的判定有正反例测试，其他项高分不能补偿失败项。
- [ ] 版本包、发布、派生新修订与人工重评继续保持不可变和可追溯。
- [ ] Alembic 从旧 head 升级和 fresh DB 均通过。
- [ ] 后端全量测试、OpenAPI 漂移检查和编译检查通过。
