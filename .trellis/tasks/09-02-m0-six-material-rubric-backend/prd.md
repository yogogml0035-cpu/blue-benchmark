# M0 六类材料与两字段评分后端

## Goal

把现有后端领域合同替换为最新 M0 模型：评测用例保存六类材料，评分维度只包含 `criterion`、`pass_score`，每项固定 10 分且必须分别及格。

## Requirements

- 每道题只有一份当前业务记录，包含辅助 `title`、六类材料、当前评分维度、场景归属、生成状态和发布状态。
- 六类材料是题目、参考样例、Bad case、与 Bad case 绑定的老师反馈、标准答案、记忆材料；不得新增独立“原始资料”模块。
- 参考样例只来自老师本次提供且 Agent 实际读取过的文件、附件、数据或内容；Agent 可以整理为与当前题目有关的文本，经老师确认后保存。不得扫描未读取文件，也不保存原文件、本地主机路径或服务端解析产物。
- 外部收题支持一次请求创建 `0..N` 道相互隔离的待处理题目，并按稳定 `client_case_id` 返回逐题结果。
- 每道题由一个独立任务要求界定；同一任务要求的多轮结果与反馈不得拆成多题。
- 每道题另有由本地 Agent 生成、管理员可修改的简短用例标题 `title`，只用于列表检索，不属于六类材料，也不参与评分维度生成；单独改名不触发重新生成。
- 批内每道题都必须有老师确认的独立标准答案，后端拒绝缺失标准答案的题目。
- Skill 的批量确认视为六类材料确认；服务端创建题目后立即为每道题排队生成评分维度，不再等待平台内二次确认或手动启动。
- 上传事务提交后的 AI 任务逐题独立运行；单题失败保留题目并提供重试，不回滚同批其他题。
- 发布前后都允许管理员修改六类材料；修改后所有基于旧内部 revision 的维度立即失效，禁止发布，直到按最新材料重新生成。
- 修改通过“保存并重新生成”单一命令提交；不保留只更新材料但继续显示旧维度的中间业务状态，也不在字段编辑过程中触发 AI。
- 批量写入必须原子完成；任一题校验或持久化失败时，整批数据库记录、评分维度生成任务和幂等回执全部回滚。
- 记忆材料由本地调用平台 Skill 的 Agent，从本次任务实际加载的记忆中筛选相关、安全的原始片段和可选安全来源标签，不绑定业务 Skill。来源可以是业务 Skill 记忆、用户记忆、本地项目记忆或其他记忆机制；不得生成摘要或保存主机路径、凭证、系统控制指令、其他任务或其他用户内容。使用者不逐条预览记忆材料。
- 多道题使用相同参考样例或记忆材料时，每道题保存独立业务内容；修改或删除一题不能影响其他题。允许按内容哈希做底层字节去重，但不能共享可变业务记录。
- 当前已发布题目中的参考样例和记忆材料为未来运行输入；标准答案、Bad case、老师反馈和评分维度不得进入被测 Skill 的运行输入。M0 不负责实际注入或执行。
- 题库统一聚合展示所有待处理和已发布题目；允许多个场景文件夹及各自独立上传凭证。场景只作为文件夹元数据，不参与题目内容或评分维度生成。
- M0 不实现题目的场景间分类、移动或复制。
- Rubric AI 基于六类材料生成 `1..N` 个两字段维度初稿。
- `criterion` 同时表达判断对象和可执行判断标准，不能只是“准确性”“创新性”等孤立标签。
- 老师可增删改两字段维度；空维度、重复 ID、空泛或不安全标准、越界分数均拒绝。
- 每项固定满分 10，`pass_score` 为整数 `0..10`。
- 未来评分语义预留为每项 `0..10` 且任一项低于本项门槛则整题不通过；M0 不实现评分执行或提交。
- 发布只标记当前题目和当前评分维度正式可用；已发布题目修改后直接覆盖并回到待处理，不保留历史版本、旧发布内容或派生草稿。内部 revision/CAS 仅用于并发控制。
- 彻底删除旧手动上传/解析/分组/共创建题、Working Set/coverage/version-package 和人工评分/重评领域，不兼容旧业务数据或旧合同。

## Acceptance Criteria

- [ ] 新外部批量收题 payload 能保存、读取、编辑并发布每道题的六类材料，且题间材料不会串用。
- [ ] 每道题可回读老师确认的参考样例整理文本，且不包含原文件、未读取文件或本地主机路径。
- [ ] 修改、删除或发布其中一道题不会改变同批其他题的参考样例或记忆材料。
- [ ] 批量创建具备全成全败、同 payload 幂等重放、变更 payload 冲突和失败后安全新命令重传测试。
- [ ] 成功批量创建后每题都有一个幂等 rubric generation job；任务可独立完成、失败和重试。
- [ ] 修改任一材料后旧 rubric 不能确认或发布；并发旧请求不能覆盖新材料或新 rubric。
- [ ] “保存并重新生成”同命令重试幂等；Worker 失败时最新材料仍可读取，且只产生一条可恢复生成链。
- [ ] 无记忆材料是合法状态；跨用户、路径、凭证和私有运行信息被拒绝。
- [ ] 测试覆盖相关记忆被保留、无关或敏感记忆被本地 Agent 排除，以及明显秘密或路径遗漏时被服务端兜底拒绝。
- [ ] OpenAPI 只暴露 `criterion + pass_score` 两字段评分维度，不再包含独立名称、说明或旧复杂 Rubric 字段。
- [ ] AI Fake 与生产结构化输出均使用六类材料和两字段维度。
- [ ] 每项必须及格的判定有正反例测试，其他项高分不能补偿失败项。
- [ ] 已发布题目修改后直接覆盖当前内容并回到待处理；不存在用户可见历史版本、旧发布内容或派生草稿。
- [ ] 当前发布内容边界保证未来 runtime 可取得题目、参考样例与记忆材料，同时标准答案、Bad case、反馈和评分维度不会泄漏。
- [ ] 旧链路专属的表、路由、服务、状态、Worker 分支、脚本和测试被完整移除，不存在兼容入口。
- [ ] 统一题库列表可同时查询待处理和已发布题目，并支持状态与场景文件夹筛选及稳定下一步动作。
- [ ] Rubric 生成对场景元数据无依赖；同材料在不同场景产生相同的输入合同。
- [ ] Alembic 从旧 head 升级和 fresh DB 均通过。
- [ ] 后端全量测试、OpenAPI 漂移检查和编译检查通过。
