# 待评文本提交与人工评分

## Goal

接收一份平台外产生的主文本或 Markdown 答卷，绑定子任务二发布的明确题目修订，由老师依据题目、单一标准答案和打分规则独立逐项评分，并保存不可覆盖、可重评的历史记录。

## Requirements

### R1. 待评文本

- 只接受直接粘贴文本或单个 `.md/.txt` UTF-8 文件；不记录 Skill 运行信息。
- 一份提交只绑定一道题的一个已发布修订，不并排比较其他答卷。

### R2. 人工评分

- 同屏展示待评文本、题目输入、标准答案、规则和阈值。
- 每项展示满分、标准答案锚点和待评得分输入；老师给整数分。最低分关键项由系统推导，一票否决关键项由老师确认是否命中。
- 低于锚点或关键项失败时理由必填；等于/高于锚点时可选。
- 服务端机械求和、执行总分 + 关键项双层判定，客户端不能覆盖结果。

### R3. 历史与重评

- 提交后的评分不可修改；重评新增 parent-linked 记录。
- 历史记录固定绑定题目修订和原答卷，可还原分项、理由和结论。

## Out of Scope

- 平台执行/识别 Skill、AI 自动打分、多答卷比较、批量评分。
- Word/PDF/图片/ZIP/多文件结果。

## Acceptance Criteria

- [ ] AC1：粘贴文本或单个合法 `.md/.txt` 可生成绑定已发布修订的独立答卷。
- [ ] AC2：越权/stale/未发布修订、超大/非 UTF-8/伪扩展文件被拒绝且不留下半成品。
- [ ] AC3：每项分数范围合法；低于锚点或关键失败无理由不能提交。
- [ ] AC4：总分与通过结果完全由服务端推导，伪造客户端总分无效。
- [ ] AC5：提交后评分不可覆盖；重评新增记录，原评分和题目修订保持不变。
- [ ] AC6：评分页不显示其他答卷或平台外运行元数据，历史页可查看已完成记录。
- [ ] AC7：答卷正文不进入日志、SSE、错误详情、版本 runtime 或其他账号响应。
- [ ] AC8：`make openapi`、`make test`、`make build`、`git diff --check` 通过。
