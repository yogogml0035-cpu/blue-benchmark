# C1 验证当前网关的 Responses Harness 完整能力

状态：已获实施批准（2026-09-08，用户批准覆盖整棵任务树）。父任务：[统一 Harness 合同](../09-08-ai-harness-contract/prd.md)。

## 目标

在不改变现有生产装配的情况下，证明当前 `gpt-5.6-luna` 与当前网关能够在保留 `medium` 时完成 Responses 下的工具往返、完整评分项生成、流式和持久化恢复，为 C2 提供可信的技术前提。

## 背景

父任务已找到实际 HTTP 400，确认当前 Chat Completions 组合失败，并在离线环境截获 Responses 候选请求。候选可被 SDK 序列化不能证明网关支持。C1 只交付能力证据，不代表原业务题目已修复。

## 需求与范围

- 复用现有 `DeepAgentRubricGenerator`、`build_restricted_agent`、完整 `RubricGenerationResult`、权限、引用校验及加密 PostgresSaver；通过已存在的模型注入入口使用原生 Responses 模型。
- 只新增受控能力探针、对应离线测试和本任务研究报告，不修改 `backend/app/`、生产配置默认值、现有业务数据或常驻服务。
- 使用当前模型、端点、medium 和原生 schema 策略；`store=false`，保留内部加密 reasoning 往返，不依赖服务端会话状态。
- 必须实际发生材料读取工具调用和工具结果回送；运行中收到真实公开增量，最终结果通过现有完整评分项与引用规则。
- 在同一协议/参数/预算下验证工具轮后恢复，使用独立子进程中断或受控故障；不降低预算再提高来伪造恢复。
- 探针必须可复跑、有限调用、拒绝项目数据库、默认不执行真实模型；真实调用需要显式 `--execute`，本任务的实施批准才授权运行。
- 报告仅记录版本、模型/协议/参数、端点 fingerprint、样本 hash、工具/模型调用数、事件时序、恢复计数和安全错误类别；不保存原始正文、凭证、私有 reasoning 或完整模型输出到 Git。

## 独立验收标准

- [ ] C1-AC1：探针默认只输出脱敏配置/资源预检，不发模型请求；缺少隔离资源或提供项目库时拒绝执行，离线测试证明无意外外连。
- [ ] C1-AC2：Responses + medium + 当前文件工具 + native schema 请求在当前网关完成至少一轮真实工具读取、结果回送和完整评分项生成，现有确定性校验全部通过。
- [ ] C1-AC3：公开增量在运行结束前收到；推理/加密块、原始工具正文和凭证不会进入报告或公开事件。
- [ ] C1-AC4：工具轮后更换执行子进程，原 checkpoint 可续跑、初始输入不重复；完成后重新读取结果不新增模型调用；模型/协议/参数/预算一致。
- [ ] C1-AC5：交付可复跑脚本、离线回归和安全能力报告，记录精确源码/SDK/配置身份；`git diff --check`、`make test`、`make build` 以及 C1 真实门在任务分支和 main 复验通过。
- [ ] C1-AC6：`backend/app/`、生产默认配置与主环境无本任务变更；父任务的生产切换仍未被冒充为完成。

C1 只有上述项目全部通过才可作为 C2 的放行凭证。若网关不支持任一必需能力，保留失败报告并返回父计划评审；不得将“成功证明不支持”登记为 C1 技术门 PASS。

## 依赖和交付

- 无实施上游依赖；开始前必须已获针对 C1 或覆盖整棵任务树的明确实施批准。
- 父子计划先交付到已验证 main，再从 main 创建 C1 专属 worktree/分支；不得读取父 worktree 未提交文件作为隐藏实施依据。
- 输出为探针、测试、任务内 `research/capability-verification.md` 和 main 交付提交；报告在实际执行后生成，本轮不生成空白“通过报告”。
- C2 必须核查 C1 完成/归档状态、全部验收通过及 main 包含交付提交后才能开始。

## 不在范围与风险

不修生产协议/指纹/错误，不新增模型路由、业务状态、外部 tracing 或共享库迁移；不重试用户原题。网关真实能力仍未知，C1 的价值正是让它在生产切换前可证伪。模型或网关配置变化会使旧能力证据失效，须复核。
