# 修复部署备份恢复与代理地址刷新

## 目标

补齐业务库、checkpoint 库和文件的成套备份恢复；服务器、OSS、Mac 各只保留最新成功的一套，控制占用，并修复应用容器更新后 Nginx 仍访问旧地址的问题。不重做业务功能或部署架构。

- 按 `trellis-brainstorm`，这些确认不代替最终规划摘要的实施门禁；本轮不运行 `task.py start` 或修改部署代码。
- 任务分支：`codex/deploy-runtime-reliability`；基线：本地 `main` 的 `6bf0d3d7c59b04fedc7198e853d86622cbe96331`。

## 已确认边界

- 用户明确：服务器数据库需要重建，服务器不使用本地数据。因此本次按全新业务库和 checkpoint 库初始化，不处理旧题兼容、旧数据转换或本地数据迁移。
- 当前部署保持单机 Docker Compose、一个 API、一个 Worker、一个 PostgreSQL 服务、Next.js 和 Nginx。数据库不对公网开放。用户截图确认目标是阿里云轻量应用服务器，系统盘为 ESSD 40 GiB；截图不含已用/可用空间，不能将容量当作可用空间。
- 用户已允许每日备份在导出期间短暂停止 API 和 Worker，完成两库及文件导出后立即恢复；OSS 上传在服务恢复后继续。停写时长由实际数据量与导出耗时决定，尚无实测秒数。
- 用户已选择“服务器 + OSS + 每日下载 Mac”三处结合，并明确要求三处均只留最新成功一套、覆盖上一版，不保留服务器 7 天或 Mac 30 天历史。新候选验证期间可以短暂与旧版共存，不能为了立即减小占用先删唯一可用备份。
- 用户接受已说明的 OSS 示例价格，计划自行申请免费试用；申请成功、账号计费资格、服务器套餐流量及实际账单尚未验证。提供教程不等于代用户开通云服务。
- Mac 下载是用户每天主动执行的维护动作，不是授权创建后台定时任务或提醒。Mac 保存服务器导出的文件，不运行或迁移本地业务数据库。
- 沿用每日备份节奏，OSS 在该日完整备份成功后更新，Mac 下载已生成的完整版本，不额外触发一次停机导出。恢复到最后一次成功备份，不提供实时、历史时间点恢复或零数据损失承诺。
- 本任务的实际操作只限仓库修改及隔离验证，不连接或清理服务器，不推送 ACR/Git 远端，不读写本地业务库，不调用真实付费 AI。

## 需求

### R1：可成套恢复的备份（P1）

- 当前 `deploy/backup.sh:30` 只导出业务库，`:34` 打包文件，`:20` 及 `:47` 保留 7 天；`deploy/restore.md:32` 只恢复业务库。checkpoint 未进入备份恢复，留存方式也不符合用户最新决定。
- 同一恢复点必须包含业务库、checkpoint 库和文件；不能用不同时间的任意两份数据库备份拼成完整恢复。
- 必须保留用于解密该恢复点的 AES 密钥；密钥单独安全保管，不输出到日志，不提交 Git，不以重新生成密钥代替恢复。
- 导出、完整性核验、上传、恢复任一步失败，都不得输出“完整备份/恢复成功”。缺少 checkpoint 或密钥时必须明确拒绝完整恢复。
- 旧的仅业务库加文件备份不能被当前流程当作完整备份使用，不新增猜测、转换或自动补齐缺失 checkpoint 的兼容路径。
- 两库及文件导出必须在已确认的停写窗口内完成，导出后立即恢复本次停止的服务；不能把“逐个 pg_dump 均成功”当作跨库一致性证据。
- 仅实现已选择的三处协作流程，不保留三选一的可切换存储后端。服务器产生归档，OSS 和 Mac 保存独立副本，每处正常完成替换后仅留最新成功的一套及必要的小型元数据。
- 服务器和 Mac 先在临时位置生成或下载候选，校验通过后整体替换当前归档；OSS 先上传并校验候选，再切换当前恢复点，最后清旧。禁止先删旧版或逐个覆盖两库文件造成混合版本。更新过程中旧版与候选短暂共存属于失败保护，不是历史留存。
- 每处只声称自己最后成功的版本。导出、上传或下载失败时保留该处上次成功的归档，三处允许暂时处于不同日期；必须显示备份 ID、生成时间和本次结果，不伪称同步完成。
- 上传或校验失败时保留上一套可用备份；旧版清理失败须明确报告，不能假称 OSS 已只有一套。版本控制、未完成分片或其他后台保留机制不能导致旧内容隐藏累积；只管理专用备份前缀，不擅自更改现有 Bucket 的保护策略或删除其他对象。
- Mac 日常优先通过服务器下载同一恢复点的完整归档并核验完整性，不默认每天从 OSS 公网下载。服务器不可用时才按恢复指引从 OSS 下载；不得把这两种来源混成不一致的一套文件，也不能承诺服务器公网下载没有费用。
- 删除旧日期历史保留逻辑、`LOCAL_KEEP_DAYS`、相关测试和维护文案，不保留旧备份格式读取转换或多种留存模式。仅业务库加文件的旧格式不是新格式完整备份；不扫描或删除用户已保存的历史备份。
- 恢复前验证目标、格式、完整性和原密钥；失败不开放写入。替换现有库和文件的后果必须清楚提示，实际服务器恢复不在本任务执行范围。

### R2：应用更新后代理不滞留旧地址（P2）

- 当前 `deploy/nginx/nginx.conf:21`、`:25` 的上游地址在加载配置时解析，`deploy/compose.yaml:17` 未声明依赖更新后的重启；`deploy/README.md:43` 和 `deploy/push-images.sh:57` 的更新流程没有地址刷新保证。
- 更新或重建 API/Web 后，即使容器内部 IP 发生变化，公开入口也能恢复访问新实例，不需要用户临时发现问题再排障。
- 登录限流、Cookie/转发头、请求 URI 与查询参数、上传限制、健康检查、SSE 实时输出等已有代理行为保持不变。
- 发布和回滚说明必须与实际实现一致，不能保留缺少必要地址刷新步骤的维护指令。
- 明确支持的 Compose 版本和运维入口，不将受控更新的保证推广为任意手动网络操作或基础设施故障下的零中断保证。

### R3：文档与隔离验收

- 同步维护中的 `deploy/README.md`、`server-setup.md`、`restore.md` 和适用配置说明，根 README 指向当前操作入口；已归档任务仅作历史证据，不改写。
- 明确区分首次空库部署、日常备份恢复和发版回滚。不能把本地 C5 的数据重置工具用于服务器。
- 在自建隔离资源上验证备份恢复和容器换 IP 后的代理行为，不依赖真实服务器、现有数据库或付费模型。
- 面向初学者说明 ACR 存软件镜像、服务器运行程序并保存当前数据、OSS 存导出的备份文件；明确备份不是在原数据库增加历史表，也不是把数据库容器镜像当成业务数据备份。开通云服务与实际恢复仍不在本任务执行范围。
- 提供与 ACR 指南同等级的 OSS 专门教程，覆盖免费试用资格核对、开通、私有 Bucket、最小权限、同地域内网访问、备份上传与下载、费用检查/提醒、保留清理和隔离恢复验证；标明哪些步骤在浏览器、Mac 或服务器执行。无需用户先自行理解全部云产品。
- 提供 Mac 每日下载步骤或受控下载入口，区分备份时间与下载时间，校验通过后覆盖本工具管理的旧归档，仅保留最新一套。未实际下载时不得声称 Mac 副本已完成；不建立按日期累积的目录，不替用户下载真实备份或删除已有 Mac 文件。
- 压缩不等于加密，归档含敏感业务数据；必须以私有权限保存，原 AES 密钥另行安全保管。

## 验收标准

- [ ] AC1 / R1：一次成功备份产生同一恢复点的两库和文件，含完整性核验信息；任一缺失、损坏或上传失败均不宣布完整成功。
- [ ] AC2 / R1：仅靠该恢复点和单独保管的原 AES 密钥，可在隔离资源中恢复题目数据、加密 checkpoint 和文件，并核对线程归属与继续执行所需状态。
- [ ] AC3 / R1：缺少 checkpoint、错误密钥或损坏备份时，恢复在重新开放写入前失败；不生成替代密钥或假造执行历史。
- [ ] AC4 / R1：停写只覆盖两库及文件导出，服务恢复后再上传 OSS；失败退出不会静默遗留本次停止的服务，并发备份不得互相干扰。文档明确可恢复到的最后成功备份时间及其后的数据损失风险。
- [ ] AC5 / R2：在隔离 Docker 网络中证明 API/Web 的 IP 确实发生变化，代理仍能访问新实例；仅重启后恰好复用旧 IP 不算通过。
- [ ] AC6 / R2：代理回归覆盖 URI/查询参数、认证转发、登录限流及 SSE 增量，不以健康端点单独代替。
- [ ] AC7 / R3：分支与合并后的 main 均通过 `git diff --check`、`make test`、`make build` 和本任务部署专项检查。
- [ ] AC8 / R3：无服务器操作、ACR 推送、真实 AI 调用、真实密钥或样本入库；现有主工作区和其他任务改动保持原样。
- [ ] AC9 / R1：服务器、OSS、Mac 连续两轮成功替换后，每处仅剩最新成功一套；各阶段失败保留原成功版本，不出现两库混搭。处理分片/版本控制残留及下载与更新并发，不依赖“先删后传”。
- [ ] AC10 / R3：Mac 下载、校验和覆盖用隔离合成归档验证；失败保留旧归档，不改无关文件，不建立日期历史目录或后台调度。教程写清每日人工执行及流量费用。

## 不在范围

- 旧题兼容层、数据转换/导入、实际服务器清库或部署。
- 修改业务 API、评分规则、AI 运行时协议、数据库业务迁移或前端页面。
- 更换 AI Provider、轮换现有密钥、扩容、HTTPS、CI/CD、跨区域灾备或新建通用备份产品。
- 自动替用户申请 OSS 试用、创建付费资源或每日提醒；下载真实服务器数据到 Mac、清理已有 Mac 文件。
- 历史备份、时间点恢复、持续复制、实时零丢失或多种留存模式。

## 风险与完成边界

- 三处只留最新增加的是存放位置的独立性，不是历史。误删或错误数据进入最新备份且三处均替换后，不能回到误删前。
- 每日备份只恢复到最后成功导出的时间；持续失败或 Mac 漏下载会扩大缺口，不承诺硬性 24 小时上限。
- 更新期间临时占用旧归档加新候选的空间。空间不足须失败保留旧版，不靠先删旧版腾空间；40 GiB 是否够用需部署前实测。
- 文件完整性校验不能判断业务内容是否正确。单独丢失原密钥或云账号/Mac 访问权仍可能影响恢复。
- 产品决策无剩余阻塞问题；技术设计见 `design.md`，执行顺序和命令见 `implement.md`。云账号、服务器可用空间及版本在实际部署前核验，不用规划或本地模拟冒充上线。
