## 目标

用两组真实会话和可控故障证明重构链路在正常、恢复、冲突与删除场景下均遵守约定，形成可复查的验收证据。

- 复用 C1 样本构建器与 C3 真实验收入口，扩展 PostgreSQL、production Worker、实际 Provider、SSE 和浏览器的系统回归。
- 覆盖后台重启、断线重连、重复/过期命令、失租与晚到写、部分清理失败和模型不可用时的删除。
- 审阅引用/老师明确要求/AI 推定、稀疏分档、人工编辑保护和本题隔离；程序断言与业务语义审阅分别记录。
- 修复本任务复现的范围内缺陷并补回归，同步受影响合同/文档，不调整已确认产品边界或降低检查标准。
- 不清理现有项目旧两库、不提前部署、不改原始语料、不启用 M1 业务或跨题检索。

## 验收标准

- 两组来源各至少一个证据完整 case 通过真实上传、生成中增量、查看依据/分档、编辑保存、发布/重开和完整删除。
- 至少验证真实 Worker 重启恢复；故障注入的 stub 结果与真实 Provider 结果分开，不用其中一类冒充另一类。
- 回放原文完整、重复消息不重复显示；图已完成未提交业务时不重跑全部模型，不覆盖人工更新。
- 删除拒绝/取消无副作用，跨库处理中不报成功，全部历次 thread/原文/缓存清干净；失租写者不能复活旧内容，兄弟题不受影响。
- 失败、缺失、跳过、版本不完整和未经老师实际确认的项目如实报告；不能用 HTTP 200、配置 production 或历史 PASS 代替本次运行身份。
- Git 中无原始正文/凭证；六个源文件 hash 不变；新回归、完整质量门和 main 上系统验收均通过。

## 完成边界

- 交付当前 main 代码的系统验收与可重放证据，不宣称当前旧演示数据库已经切换；部署交付由 C5 完成。
- 若发现缺失基础能力或仍可执行的旧语义，作为阻塞缺陷修复并重跑，而不是让 C5 带病发布。
