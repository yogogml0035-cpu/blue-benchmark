- 核查 C3（09-06-m0-rubric-atomic-cutover）完成记录、核心真实验收与 main 包含的提交；C1/C2 的实际接口从该 main 获取。

## 执行顺序

1. 对 C3 已交付入口跑基线，确认生产链路和两组真实样本核心验收确实可复现。
2. 扩展后台、前端和集成测试，按 design.md 矩阵做故障注入，所有进程和数据库操作限定为本次资源。
3. 修复复现的范围内缺陷，补最小回归并同步类型/规格；保留失败证据，不降低独立预期或偷偷换样本。
4. 在实际 Provider + production Worker + PostgreSQL + 浏览器链路跑正常与至少一次重启恢复，检查流式原文和完整删除的存储结果。
5. 整理脱敏运行报告、case/operation/thread 关联、未覆盖项和可重放命令，私有证据按父任务产物策略保存。
6. 分支通过完整质量门后合入 main，在 main 重跑系统验收并记录 SHA；通过后交接 C5。

## 质量门

```bash
git diff --check
make test
make build
make frontend-e2e
make ai-smoke
make accept-web
```

- 最后两个入口必须使用 C3 已接入的真实样本配置和隔离 PostgreSQL；还需执行 backend 的真实集成 runner 和本任务新增故障测试。
- 明确新生成、普通编辑、确认重生成、回放、恢复、删除各自通过条件，不用单一 PASS 掩盖未执行环节。
- 检查 no-placeholder、no-legacy、无跨题数据与模型不可用仍可删除；记录源文件 hash 和 Git 敏感内容检查。
- main 复验前确认测试对应当前提交，不能复用分支页面、另一个端口服务或上一轮结果。
