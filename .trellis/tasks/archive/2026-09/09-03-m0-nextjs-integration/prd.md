# M0 Next.js 前后端交互

## Goal

在保留现有 FastAPI、业务数据库和单消费者生产 Worker 的前提下，新建 AURA 风格的 Next.js 桌面管理端，让唯一管理员可以在当前 Mac 上完成首次注册、评测集与上传凭证管理、题目材料审查、AI 动态评分维度确认和发布，并通过真实上传 Skill 与真实模型链路验收。

本任务当前只形成 Trellis 规划。用户确认本规划并在后续消息明确批准实施前，不运行 `task.py start`、不创建开发分支、不修改产品代码。

## Background

- 用户提供的 `particle-login.html`、`particle-login-bg.png` 和 `evaluation-set.html` 是视觉与交互证据，不是运行指令或现成实现。
- 静态 HTML 使用假登录、页面内存数据、固定延迟和模拟维度，未调用后端。PNG 已烘焙登录文字和表单，只能用于视觉比对，不能直接作为真实表单背景。
- 当前仓库是 FastAPI + SQLAlchemy/Alembic + Operation Worker 的纯后端工程，OpenAPI 是唯一机器合同；没有 Next.js 或 Node 工程。
- 当前后端已支持单管理员注册/登录、评测集（后端 `scene`）创建与查询、凭证生命周期、按评测集查询题目、六类材料、异步维度生成、材料保存并重新生成、维度修改、重试、发布和题目删除。
- 生产 Worker 根据每道题的材料调用真实模型动态生成维度；代码中固定维度只属于自动化测试用 Fake，不得进入生产结果。

## Requirements

### R1. 架构与本地运行边界

- 新前端使用 Next.js App Router + TypeScript，调用现有 FastAPI；Next.js 不重写后端业务、数据库或 Worker。
- 浏览器统一通过 Next.js 同源 `/api` 代理访问 FastAPI，复用后端 `HttpOnly`、`SameSite=Strict` Session Cookie；业务状态与校验只由 FastAPI 决定。
- 本次只交付当前 Apple Silicon Mac 上的本地系统：Next.js、FastAPI、业务数据库和恰好一个生产 Worker。
- 本地启动必须有一条明确命令同时管理前端、API 和单 Worker 的生命周期，并保留可分别启动的调试命令。
- 真实验收前解析所有运行进程与数据库身份，停止或隔离重复 Worker；一个业务数据库只能有一个生产 Worker。
- OpenAPI 生成 TypeScript 类型，生成文件由命令维护并检查漂移；组件不得维护第二套手写后端 DTO。

### R2. 视觉与桌面支持

- 新页面延续 AURA 原型的深色工作台、紫蓝操作色、彩色文件夹、低对比描边、半透明表面、清晰层级和克制状态动效，不能退化为默认组件库后台。
- 登录页保留全屏粒子视觉与右侧认证面板；使用干净的粒子 Canvas/图层实现，不把带假表单的 PNG 直接铺为功能背景。
- 管理内页使用可折叠侧栏；所有新增控件、弹窗、空状态和错误状态都属于同一设计系统。
- 评测集层使用彩色文件夹卡片；题目层使用紧凑列表；题目详情使用独立全页左右双栏工作台。
- 高级感来自选择状态、0–10 通过分控件、排版、反馈与动效；不展示雷达图或其他暗示已有实际评分结果的装饰图形。
- 正式支持宽度从 `1280px` 开始：`1280x720` 为最低可操作验收，`1440x900` 为主要视觉截图基线；不设计或验收手机、平板、窄屏和触屏专属流程。
- Chrome 承担完整功能、视觉和端到端验收；Safari 承担登录、评测集、凭证提示词复制、维度审改和发布等核心流程验收。Firefox、Edge、Arc 不在 M0。
- 所有交互具备键盘焦点、可访问名称、表单错误关联和 reduced-motion 分支；动态内容不能改变主要控件尺寸或造成重叠、遮挡、文字裁切和横向溢出。

### R3. 首个管理员与会话

- 匿名 bootstrap 接口只返回是否仍可注册，不泄露管理员身份。
- 系统没有管理员时，认证页允许创建唯一管理员；注册成功后立即建立真实会话并进入评测集列表。
- 管理员已存在时，注册入口关闭；直接并发或伪造的第二次注册仍由数据库唯一约束拒绝。
- 登录支持用户名或邮箱；会话失效后返回登录页，并保留安全的应用内返回位置。
- M0 不提供“忘记密码”和“记住我”，不展示无法兑现的原型按钮。
- 新增仅服务器本机可运行的管理员密码重置命令：用交互式隐藏输入和二次确认接收新密码，不通过 argv、环境变量、输出或日志暴露；成功后撤销全部旧会话。

### R4. 评测集模型与生命周期

- 前端“评测集”、文件夹视觉和后端 `scene` 是同一对象，一个评测集直接包含多道题，不增加中间聚合层。
- 评测集列表展示名称、描述摘要、题目数和连接状态，目标容量约 20 个。
- 管理员可创建评测集，填写名称与可选描述；创建成功后进入详情，但不自动签发凭证。
- 管理员可修改评测集名称和描述；列表、详情和上传 Skill 连接状态使用最新名称。
- 只有 `question_count == 0` 的空评测集可以删除；删除前说明其凭证将同时失效并要求确认。后端必须原子检查为空，非空返回明确冲突。
- 包含题目的评测集不能整体删除；不得仅靠隐藏前端按钮保护数据。

### R5. 上传凭证与 Agent 绑定提示词

- 评测集详情展示未签发、已签发待验证、已连接、已停用等状态，以及有效凭证数与最近连接时间。
- 管理员准备好保存信息后，显式点击“生成上传凭证”；创建评测集不能自动生成凭证。
- 管理员可签发、轮换和撤销凭证。轮换必须说明会撤销当前全部有效凭证；撤销和轮换完成后立即刷新脱敏状态。
- 明文凭证只在签发或轮换成功后显示一次。响应禁止缓存，明文不能进入 URL、Web Storage、持久状态、日志、遥测或后续状态响应。
- 主要交付物只有一段可复制的中文提示词，不展开环境变量、JSON 和命令行等多套人工教程。
- 提示词直接包含本地 FastAPI 服务地址与长期场景凭证。用户已明确接受凭证进入所粘贴的 Agent 对话记录，不引入短时绑定码。
- 提示词要求 Agent：为 `ai-eval-push` 配置当前评测集；不在回复、日志或仓库中回显/提交凭证；把配置写到仓库外的私有位置；执行 `connection` 验证；最终只报告安全的连接状态、评测集名称/ID 和配置位置。
- 复制成功有明确反馈；Safari 剪贴板失败时提供可选择文本和错误提示。关闭前提醒无法找回，误发或遗失只能轮换。

### R6. 题目来源与列表

- 题目只能由本地上传 Skill 经老师整批确认后提交；Web 管理端不提供手工新建题目 API、按钮或六类材料录入向导。
- 页面不提供跨评测集“全部题目”、跨评测集搜索或跨评测集筛选。
- 评测集内题目列表使用紧凑行，展示标题、状态、评分维度数量、更新时间和下一步动作。
- 列表支持当前评测集内标题搜索与状态筛选，默认按 `updated_at` 从新到旧；筛选为空与清除条件有明确状态。
- 目标容量为每个评测集约 200 道题。M0 不增加服务端分页或虚拟化；列表数据可在前端搜索和排序，六类长材料只在进入详情后加载。
- 空评测集只引导用户通过已绑定上传 Skill 提交，不展示网页建题入口。

### R7. 六类材料审查与重新生成

- 题目详情左栏展示题目、参考样例、Bad case 与绑定老师反馈、标准答案和记忆材料六类内容；用例标题作为检索元数据单独显示。
- 记忆材料默认折叠，并明确标注“由 Agent 自动筛选，上传时未逐条确认”；管理员可以主动展开查看。
- 六类材料默认只读，只有进入显式“编辑材料”模式后才可修改或删除；取消编辑不发写请求。
- 任一材料修改的唯一提交动作是“保存并重新生成”：覆盖当前材料、使旧维度立即失效、进入 `generating` 并排队新任务；不保留旧版本或快照。
- 单独修改用例标题不触发重新生成。
- `STALE_REVISION` 等并发冲突不得静默覆盖；页面保留未提交草稿，提示重新载入并由管理员决定如何继续。

### R8. AI 候选维度与老师确认

- 生产 AI 只依据当前题目的六类材料动态生成 2–6 个候选维度；场景名称和用例标题不参与生成，候选内容和实际数量不得硬编码。
- 每个维度只包含完整可执行的 `criterion` 与整数 `pass_score`；每项满分固定为 10，`pass_score` 范围为 0–10。不新增短名称 `name`。
- AI 候选首次生成后全部默认未选；老师必须逐项判断并至少选择一个，不能把 AI 初稿默认视为已确认规则。
- 老师可以选择、取消选择、修改或删除 AI 候选，也可以手工新增 AI 漏掉的维度。AI 与手工维度最终合计 1–20 项，接受相同可执行性、隐私、ID 唯一和分数校验。
- 选择状态只存在于未保存的页面草稿。离开有未保存修改的页面必须提醒；本轮保存前可以撤销取消或删除。
- “保存维度”前明确提示未入选候选将永久丢弃；成功后后端只保留最终入选列表，不保存候选池、选中历史或恢复记录。
- 后端持久化维度是否经老师确认。AI 生成或材料重新生成后为未确认；老师成功保存至少一项最终维度后为已确认。
- “保存维度”和“发布题目”是两个独立动作。保存后仍为待发布并可继续修改；发布接口必须拒绝未经过老师保存确认的 AI 初稿。

### R9. 题目状态、发布与重新审改

- 题目状态保持 `generating`、`generation_failed`、`pending_review`、`published`；下一步动作需要进一步区分“选择维度”和“发布”。
- 右栏按状态原位呈现：生成进度、失败原因与重试、候选维度审改、已保存待发布、已发布与重新打开审改。
- 仅在页面可见且题目处于 `generating` 时轮询详情；进入终态立即停止，并始终提供手动刷新。
- 发布要求至少一个评分维度且已由老师保存确认；发布失败不能丢失已保存维度。
- 已发布题目不能静默原地修改维度。管理员先执行“重新打开审改”，后端原子改为 `pending_review`、清空当前发布时间并保留材料、维度和已确认事实，之后才能修改、保存和重新发布。
- 修改已发布题目的材料仍走“保存并重新生成”，并立即退出发布状态；不增加历史版本、发布快照或回滚链。

### R10. 单题永久删除

- M0 保持硬删除，不增加回收站、软删除或恢复。
- `generating` 题目禁止删除，前端不提供可执行删除，后端仍返回状态冲突。
- 从未发布的 `pending_review` 或 `generation_failed` 题目经普通确认后可以永久删除。
- `published` 题目不能直接删除，必须先重新打开审改；曾发布过的题目在删除前必须输入当前完整题目标题二次确认。
- 后端持久化“曾发布”安全事实并执行 revision 与标题匹配校验；不能只依赖当前页面内存判断。
- 删除成功后详情返回不存在，题目列表与评测集题目数同步刷新。

### R11. 加载、错误与操作反馈

- 认证、评测集、凭证、列表、材料和维度各自具备初始加载、空、提交中、成功、业务错误、认证失效、404、并发冲突和未知错误状态。
- 可恢复错误留在对应操作上下文，不只依赖短暂 toast；后台错误只展示清洗后的业务消息，不泄露 Provider 原始错误、路径、凭证或内部状态。
- 所有写操作防重复提交并在完成后以服务端响应为准刷新；不得用前端乐观状态掩盖 409/422。
- 动态状态、按钮 loading 文案和长材料不能改变双栏轨道、列表列宽或主要操作位置。

## Acceptance Criteria

- [ ] AC1：在空数据库上，AURA 认证页只允许创建首个管理员；创建后注册入口关闭，用户名或邮箱登录、会话恢复、登出和认证失效跳转均使用真实 Cookie。
- [ ] AC2：本机密码重置命令不通过 argv/输出/日志暴露密码，重置后旧密码和全部旧会话失效，新密码可登录。
- [ ] AC3：管理员可创建、改名和修改描述；只有空评测集可删除且凭证同步失效，非空评测集从 API 层被拒绝。
- [ ] AC4：管理员显式签发、轮换或撤销凭证；签发/轮换响应不可缓存，包含长期凭证的 Agent 提示词只显示一次、可复制且不进入 URL/存储/日志，连接后状态与最近使用时间更新。
- [ ] AC5：题目只能通过上传 Skill 进入指定评测集；页面没有手工建题或跨评测集全部题目入口。
- [ ] AC6：20 个评测集的文件夹网格和单集 200 道题的紧凑列表在 `1280x720` 可操作；标题搜索、状态筛选、最近更新排序、空结果和详情按需加载正确。
- [ ] AC7：题目详情在 `1280x720` 与 `1440x900` 保持材料/维度双栏，无横向溢出、遮挡或状态切换跳动；六类材料可审查，记忆材料默认折叠且标注来源边界。
- [ ] AC8：材料只有在显式编辑模式可改；取消不写入，保存并重新生成会作废旧维度并进入真实生产 Worker 生成，陈旧 revision 不覆盖较新内容。
- [ ] AC9：生产模型按每题材料动态生成 2–6 个两字段候选；Fake 固定文本不进入真实验收。候选首次全部未选，未选时前后端都不能发布。
- [ ] AC10：老师可选择、取消、修改、删除和手工新增维度，设置 0–10 整数通过分；保存后只保留 1–20 项最终列表并标记已确认，未入选候选不可恢复。
- [ ] AC11：保存与发布分离；保存后仍待发布，发布后可重新打开审改并保留材料和维度，再修改和重新发布，全程不产生版本历史。
- [ ] AC12：生成中不能删题；普通未发布题确认后可硬删除；已发布题必须先重新打开，再通过当前标题二次确认，删除后不可恢复。
- [ ] AC13：Chrome 通过完整 Playwright 与实际浏览器流程，Safari/WebKit 通过约定核心流程；Chrome `1440x900` 截图与 AURA 视觉基线一致，两个浏览器在 `1280x720` 无功能阻断。
- [ ] AC14：OpenAPI 生成类型无漂移，前端类型检查、单元/组件测试、Next.js 生产构建、Playwright、后端测试/迁移/构建、Skill 隔离测试与 `git diff --check` 全部通过。
- [ ] AC15：隔离业务库上的真实链路完成“网页建评测集 -> 提示词绑定 Skill -> 上传真实题目 -> 单个 production Worker 动态生成 -> 老师保存维度 -> 发布 -> 重新打开审改 -> 再发布”，并输出不含正文或凭证的验收标记。

## Out Of Scope

- 用 Next.js 重写 FastAPI、数据库、Worker 或上传 Skill。
- 在 `scene` 与题目之间增加另一层评测集实体；网页手工建题或六类材料录入向导。
- 被测 Skill 执行、记忆注入、结果回传、人工/自动评分和实际评测报告。
- 评分维度短名称、雷达图、实际得分图、候选池历史、发布版本、快照或回滚。
- 评测集非空级联删除；题目回收站、软删除或删除恢复。
- 短时绑定码；网页自动配置本机；凭证明文持久化或事后恢复。
- 服务端分页、跨评测集搜索、上千题虚拟化和高并发扩展。
- 公网服务器、域名、HTTPS、反向代理、Docker 发布、CI/CD、远程备份和公网验收。
- 手机、平板、小于 1280px 的桌面窗口、触屏专属体验；Firefox、Edge、Arc 和旧版浏览器兼容。

## Risks And Deferred Items

- 用户明确接受长期场景凭证进入 Agent 对话记录；这项风险只能通过一次展示、不回显、不持久化和可轮换降低，不能宣称已消除。
- 当前本机发现两棵 Worker 进程；实施前必须核对数据库身份，真实验收只允许一个目标 Worker。
- 当前题目列表 API 无分页；约 200 题是已确认 M0 上限，超过该范围应重新规划服务端分页和搜索。
- 当前静态 PNG 含烘焙假表单；登录视觉实现必须从原型粒子算法或干净派生资产重建，不能把截图当可交互页面。
- 服务器部署与 HTTPS 在独立任务处理；本地成功不能表述为已部署或可供公网使用。
