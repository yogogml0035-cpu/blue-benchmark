# PRD：ai-eval-push 技能凭证硬编码绑定机制

## 背景与目标

`ai-eval-push` 技能负责把会话中完成的真实工作整理成评测题并上传到 Skill Eval Platform 题库。当前脚本 `push_eval_cases.py` 通过环境变量（`AI_EVAL_BASE_URL` / `AI_EVAL_ACCESS_TOKEN` / `AI_EVAL_CONFIG`）读取平台地址与场景凭证。

该技能的使用场景是**按场景分发给团队**：凭证是场景级共享的，希望一次绑定后把整个技能打包发给同事，同事零配置即可使用。环境变量机制与此冲突——凭证需要落在每台机器的环境里，无法随技能分发，且存在凭证流入 shell 配置、会话日志的风险。

本任务把凭证承载方式改为**脚本内硬编码常量**：出厂为占位符，绑定 = 把占位符直接替换为真实值。

## 旧语义（不再支持）

- 脚本不再读取 `AI_EVAL_BASE_URL`、`AI_EVAL_ACCESS_TOKEN`、`AI_EVAL_CONFIG` 环境变量；`load_config()` 中的环境变量与配置文件链路整体删除，不保留兼容分支、不做双轨读取。
- SKILL.md 中“配置”一节关于环境变量的说明整体重写为绑定流程。
- 测试中所有通过 `monkeypatch.setenv` 注入配置的用法全部改写。

## 新行为

1. **凭证硬编码**：`push_eval_cases.py` 顶部声明两个模块级常量，出厂值为占位符：
   - `BASE_URL = "***"`
   - `ACCESS_TOKEN = "sep_***"`
   占位符含 `***` 即视为未绑定。
2. **绑定 = 直接替换**：用户在对话中发送平台地址与凭证并要求绑定时，Agent 用编辑工具把脚本中两个占位符替换为真实值。不提供 `bind` 子命令，不读取任何环境变量或外部配置文件。
3. **未绑定保护**：任一命令（`connection` / `validate` / `push`）在常量仍为占位符时以 `config-error` 退出（exit 2），错误信息指明“凭证未绑定，请发送凭证与平台地址让 agent 绑定”。
4. **绑定校验**：绑定后运行 `connection` 验证——打印绑定的场景名等已知安全字段；任何输出（含错误输出）绝不回显完整 token。
5. **仓库副本铁律**：仓库（有 GitHub 远端）中的脚本永远保持占位符状态；绑定只发生在部署副本（如 `~/.agents/skills/ai-eval-push/`）与对外分发的打包副本上。绝不把绑定后的脚本提交进仓库。

## 分发与生命周期（运营约定，无代码机制）

- 分发者在本机部署副本上绑定 → 打包发出；接收者零配置即用。
- 接收者若要用自己的新场景：自建场景、对副本中的常量做同样的替换。
- 凭证泄漏/轮换：平台侧轮换后旧凭证失效，分发者重新绑定并重新分发；不做任何副本防护机制（经需求方确认接受）。

## 验收标准

1. 占位符状态下运行 `connection` / `validate` / `push` 均返回 `config-error`（exit 2）并提示绑定，不发起任何网络请求。
2. 把常量替换为有效值后，`validate` 与 `push` 的行为与改造前一致（校验逻辑、隐私兜底、幂等 `command_id`、错误码转述均不变）。
3. 全仓库检索 `AI_EVAL_BASE_URL`、`AI_EVAL_ACCESS_TOKEN`、`AI_EVAL_CONFIG` 三个标识符：除本任务文档（`.trellis/tasks/`）外无任何命中。
4. `skills/ai-eval-push/tests` 全部通过；`git diff --check` 干净。
5. 仓库中的脚本保持占位符状态（合并前确认无真实凭证入库）。
6. SKILL.md 的“配置”节改为绑定流程说明，并包含：绑定步骤、绑定后验证、未绑定报错的处理、仓库副本不绑定的警示、分发给同事的说明。

## 范围边界

- 平台侧（凭证 1:1 模型、明文可见、小眼睛交互）由姊妹任务 `09-04-platform-credential-one-to-one` 承担，不在本任务内。
- 本地 `~/.agents/skills/ai-eval-push/` 部署副本的替换在本任务合并入 `main` 后执行（父任务收尾步骤），替换后为占位符状态，等待首次绑定。
