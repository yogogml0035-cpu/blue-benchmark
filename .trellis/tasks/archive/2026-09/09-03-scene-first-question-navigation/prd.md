# 场景优先题库导航与接口收紧

## Goal

把 M0 的题库入口从“全部题目 + 场景筛选”改为“场景列表 → 场景内题目列表 → 题目详情”，并在后端合同中禁止无场景的全量题目查询，确保未来前端无法重新引入混杂的全部题目视图。

本任务只创建修改计划。用户后续明确批准实施前，不修改交接稿、后端代码、OpenAPI 或测试，也不运行 `task.py start`。

## Requirements

- 场景是题目导航与归属的第一层，不是题目列表上的普通筛选标签。
- 系统首页/首要入口展示场景列表；点击场景后，只显示该场景中的题目。
- 不提供“全部题目”页面、跨场景搜索或跨场景筛选。
- 场景内可以按题目状态筛选，例如生成中、生成失败、待确认、已发布。
- 保留现有场景创建、场景列表、场景状态和凭证生命周期能力。
- 保留题目详情及编辑、重新生成、维度编辑、重试、发布和删除能力。
- 管理员题目列表接口必须提供有效 `scene_id`；缺少参数时拒绝请求，不得退化为返回全部题目。
- 不存在的 `scene_id` 返回明确 404，而不是伪装成空场景列表。
- 场景凭证上传流程不变：凭证决定题目归属，上传 payload 仍不能提交或覆盖 `scene_id`。
- OpenAPI、README、测试和前端交接稿必须使用同一“场景优先”口径。

## Acceptance Criteria

- [x] 前端交接稿的主流程明确为“场景列表 → 场景题目列表 → 题目详情”。
- [x] 交接稿不再描述统一大题库首页、全部题目入口或按场景筛选全部题目。
- [x] 场景页面包含创建场景入口和场景卡片；场景卡片至少表达名称、题目数量和进入动作。
- [x] 场景内题目列表只展示当前场景内容，并保留状态筛选与下一步动作。
- [x] `GET /api/questions` 的 `scene_id` 在 OpenAPI 中为必填。
- [x] 不传 `scene_id` 返回 422；传入不存在的场景返回 404；有效场景只返回该场景题目。
- [x] 两个场景同时有题时，没有任何管理员列表接口可一次返回跨场景全部题目。
- [x] 场景 CRUD、凭证、外部批量上传和题目详情/编辑/发布行为不回退。
- [x] README、OpenAPI 漂移检查、后端测试和构建门禁通过。
