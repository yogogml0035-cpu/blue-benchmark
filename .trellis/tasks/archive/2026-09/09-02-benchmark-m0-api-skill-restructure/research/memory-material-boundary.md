# M0 记忆材料边界

## 新增目的

本地 Agent 在执行任务时可能加载多种记忆，包括业务 Skill 记忆、用户长期偏好、本地项目规则或历史经验。只要这些内容实际进入本轮上下文，就可能影响最终生成结果。若评测题遗漏它们，未来复现时可能把“背景资料缺失”误判成能力退化。

因此评测用例从五类材料扩展为六类，新增“记忆材料”。

## 已确认边界

- 只从本次任务实际加载并进入上下文的记忆中选取材料。
- 来源可以是业务 Skill、用户、本地项目或其他记忆机制，不绑定某个 Skill。
- 不扫描或上传任何完整记忆库。
- 不上传未在此次任务使用、仅被认为“可能相关”的记忆。
- 不上传其他任务、其他用户、凭证、系统控制指令、内部 Agent 状态、本地主机路径或存储索引。
- 本地调用平台 Skill 的 Agent 负责判断相关性与敏感性；无关或敏感片段不进入 payload。
- 使用者不逐条预览或确认记忆材料，避免增加操作负担。
- 本次没有读取记忆时允许为空，并明确记录“未使用记忆”。
- 只保存原始记忆内容，不生成或保存 AI 提炼摘要。
- 被 Agent 选中的内容仍保存原始记忆文本，不生成摘要或改写版本。
- 服务端对路径、凭证、系统控制字段等明显风险做兜底拒绝，但不代替本地 Agent 判断业务相关性。

## 为什么不能与参考样例合并

- 参考样例是老师本次直接提供给 Agent 的文件、附件、数据或内容。
- 记忆材料是本轮从已有记忆机制加载的背景资料；它可能来自业务 Skill，也可能来自用户或本地项目。
- 两者来源、授权和复现意义不同。合并后无法判断未来运行缺失的是业务资料还是用户偏好。

## 未来执行边界

- 未来运行评测时，记忆材料需要作为背景上下文提供给执行环境，才能复现原任务条件。
- 它应以独立的“记忆输入”身份进入 runtime，而不是混入任务要求或参考文件。
- 标准答案、坏样本、老师反馈和评分规则仍属于 judge/provenance，不能同时泄漏给被测 Agent。
- 当前 M0 不实现取题、记忆注入、Skill 执行、结果回传或自动评分，只保证当前发布内容具备未来可用的数据边界。

## 已关闭的分叉

不要求把所有已加载记忆原样上传，也不要求老师逐条审阅。采用“本地 Agent 自动过滤无关与敏感内容，只上传相关、安全原文；服务端做确定性泄漏兜底”的边界，以减少老师工作量。
