# 题目详情自由编辑与全站字体改版

## Goal

题目详情页从「页面级编辑模式 + 保存即重新生成」改为「自由编辑模型」：材料逐模块直接编辑、失焦自动保存，重新生成独立成按钮且只重跑评分维度；评分维度勾选只承担绑定职责，内容随时可改；新增依据失配软提醒；凭证 `label` 死字段整条删除；全站建立字号 token 体系并整体上调。

## 背景与动机

- 现状痛点（2026-09-07 截图访谈确认）：
  1. 凭证卡片恒显示「未命名凭证」——`label` 字段前端从不传、恒为 NULL，是只会显示默认值的死字段；
  2. 「编辑材料」按钮把整页拖入编辑模式，保存与"重新生成维度"捆绑，语义混乱；
  3. 评分维度必须勾选才能编辑内容，勾选的绑定职责与编辑职责耦合；
  4. 全站正文 14px、大量 12/13px 写死小字，页面密密麻麻。
- 用户决策（访谈逐条确认）：
  1. 材料任意模块可改，自动保存（失焦/停顿落盘），无保存按钮；
  2. 「重新生成」独立按钮放「删除题目」旁，无条件只重跑评分维度生成（材料从来不被 AI 重新生成）；
  3. 编辑触发：悬停边框高亮 + 铅笔按钮（单击），双击为快捷方式；
  4. 勾选框只管绑定（进入最终 1–20 项），维度内容不选中也能改；
  5. 依据过期采用软提醒（检测失配显示提醒条，不阻断）；
  6. 字体全站统一 +2px、正文行距 1.5→1.7，建立字号 token。

## 旧语义（本任务后不再受支持）

- `POST /api/questions/{question_id}/save-regenerate`（保存并重新生成合并接口）及前端 `saveRegenerate` 调用、页面级编辑模式（`editingMaterials`/`materialDraft`）、「编辑材料」按钮；
- 「未勾选维度不可编辑内容/通过分/分数表现说明」的 readOnly 门控；
- 凭证 `label` 字段全链路（请求 Schema、`_validate_label`、模型列、状态视图字段、前端显示）；
- 以上入口全部不可用即验收通过，不保留兼容层、双轨读取或隐藏入口。

## Requirements

### R1 凭证 label 整条删除

- 后端：`SceneCredentialIssueRequest.label`、`_validate_label`、凭证模型 `label` 列、`SceneCredentialStatusView.label`、`SceneConnectionStatusView.label` 全部删除。
- 新增迁移 0022 drop `label` 列（含 downgrade）。
- 前端：凭证卡片删除名称行与「未命名凭证」兜底文案；停用按钮 aria-label 改用掩码 token。
- `make openapi` 与 `make frontend-generate-api` 同步再生成。

### R2 题目详情页布局

- 删除 header 行的「编辑材料」按钮。
- 右列「评分维度」标题与「查看完整生成过程」合并为一行：标题居左、按钮居右。
- 左列首模块「题目」标题与右列「评分维度」标题顶部对齐。

### R3 左列材料逐模块自由编辑（自动保存）

- 编辑范围与现状编辑模式一致：题目、标准答案、每个参考文本、每个 bad case、每条用户记忆、用例标题；不新增条目增删能力（现状不具备）。
- 触发：悬停模块卡片边框高亮 + 卡片右上角浮现铅笔按钮，单击进入编辑态；双击卡片为快捷方式；失焦自动保存并回到阅读态。
- 保存语义：每模块一个轻量更新请求，只写文本，不触发任何生成、不推进 `content_revision`、不动评分维度。
- 用例标题在 header 行内点击即可编辑，失焦自动保存（沿用现有 title 接口）。
- 自动保存失败（网络/校验）时卡片给出可见的失败提示与重试入口；不做本地持久队列。

### R4 右列评分维度解耦

- 勾选框只承担"进入最终已选集合"的绑定职责；维度标题/描述/通过分/分数表现说明未勾选也可编辑。
- 维度内容修改自动保存（字段级接口），不改变勾选状态、确认状态，不丢弃未入选候选。
- 「保存维度」保留为最终确认动作：现有确认弹窗与"未入选候选永久丢弃"语义不变。

### R5 重新生成独立按钮

- header 上「重新生成」按钮位于「删除题目」旁；点击弹确认（明示"已选/已确认评分维度将全部作废重来"），确认后无条件重跑维度生成流水线。
- 行为与现有 save-regenerate 的生成部分一致：推进 `content_revision`、清空 `criteria_json`/`criteria_confirmed`、入队生成；材料以当前已保存内容为准。
- 删除旧 save-regenerate 接口；材料编辑与生成彻底解耦。

### R6 依据失配软提醒

- 材料更新后重算"已确认维度依据文本是否仍能在当前材料中找到"（复用现有 locator 校验逻辑）。
- 存在失配时，评分维度区顶部显示提醒条：「材料已修改，部分维度依据引用的原文已过期，建议重新生成或检查依据」；不阻断任何操作。
- 题目详情响应携带失配标记（布尔）。

### R7 全站字体体系

- `globals.css` 建立字号 token（与现有颜色/圆角 token 同体系），替换各 CSS Module 写死的 px。
- 档位整体 +2px：11→13、12→14、13→15、14→16（正文基准）、15→17、16→18、18→20、20→22；登录页 clamp 大字除外。
- 正文行距 1.5→1.7。
- 字号变大导致的布局溢出（表格、徽章、状态条等）逐页修复。

## Acceptance Criteria

1. 凭证卡片不再显示任何名称行；后端全仓无 `label` 凭证字段残留（迁移后库中列已删除），带 `label` 的旧请求不报错也不生效。
2. 题目详情页无「编辑材料」按钮；「评分维度」与「查看完整生成过程」同行；两列标题顶部对齐。
3. 悬停左列模块出现边框高亮与铅笔按钮，单击或双击进入编辑，失焦后刷新页面内容仍为修改后文本（已落库），期间无任何生成任务入队、`content_revision` 不变。
4. 未勾选的维度可直接修改描述/通过分/分数表现说明并落库；勾选/取消勾选后按「保存维度」，最终集合与确认状态正确，未入选候选按现有语义丢弃。
5. 点击「重新生成」确认后：旧维度全部作废、生成任务入队、完成后出现新候选；「保存并重新生成」接口不存在（404/405）。
6. 修改材料使某维度依据原文失配后，评分维度区出现提醒条；将材料改回或重新生成后提醒消失。
7. 全站各页面字号符合新档位表，正文行距 1.7；无文字溢出/截断破版。
8. 质量门：`git diff --check`、`make test`、`make build` 通过；E2E 用生产构建跑通；全页面截图视觉验收通过。

## 非目标

- 材料条目增删（新增参考文本/bad case/记忆条目）——现状编辑模式不具备，本任务不引入。
- 多标签并发编辑冲突合并——单管理员内部工具，接受 last-write-wins。
- 移动端适配。
- 依据失配的硬阻断或自动修复。
