## 拆分判断

当前完整 Responses 能力尚未在网关验证，这个结果会决定生产修复方案是否成立。C1 能在不改生产装配的条件下交付可复跑探针和兼容性事实，因此值得独立验收。协议、恢复指纹、错误分类和旧路径删除共同构成一次运行语义切换，拆开合并可能留下不安全的中间状态，全部归 C2；C2 的测试和真实系统验收也不再拆成后续任务。

## 验收归属

|---|---|---|
| AC1、AC2 | L01 能力门，证明方案可行；不等于生产接入验收 | C2 必须通过最终生产入口重跑 |
| AC3、AC4、AC6 | 只报告本次探针事实，不修生产重试或诊断 | C2 |
| AC5 | 验证原生 Responses 工具历史和 checkpoint 恢复可用 | C2 验证真实 Worker 的恢复、指纹切换和业务提交 |
| AC7、AC8 | 自身脚本门禁和 main 复验，不替代最终业务回归 | C2 完成全部业务与主分支验收，父任务复核证据 |

## 依赖执行规则

- 原生 `parent`/`children` 表示归属，不会自动阻止提前开工；`meta.depends_on` 同样只是声明。
- C2 开始前必须人工确认 C1 已完成/归档、能力结论为 PASS、所有 C1 验收项通过，且交付提交存在于当前已验证 main。仅有分支代码、task.py validate 或失败报告都不放行。
- 比对 C1 的模型、端点 fingerprint、effort、策略、SDK 版本和源码身份；这些前提变化时先在隔离环境复核能力门，不能用旧报告证明新配置可用。
- C1 如果证实当前网关不支持目标组合，保存失败证据并返回父计划评审，C2 不启动。不得自动 none、换模型、开服务端存储或减小 schema。
- 当前所有计划存在父规划 worktree。子任务批准开工时各自创建独立分支/worktree；task.json 的 planned_* 不是已经存在的工作区。
- 子任务从已验证 main 开始。开工前先把最终批准的计划材料通过规划分支提交/集成到 main，遵守该文档变更的质量门；不能从未提交父 worktree 复制隐藏上下文或从未交付的子分支启动。
- 合并与 main 复验串行。C1、C2 都在自身交付闭环中验收和清理；父任务最后核查全部交付后才归档。
