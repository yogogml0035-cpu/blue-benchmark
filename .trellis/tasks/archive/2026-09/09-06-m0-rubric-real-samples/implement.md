# C1 实施与验收

## 进入条件

- 先读父任务 task-map.md；本任务无前置子任务，但任务树文档必须已进入可供子 worktree 获取的 main 基线，且已有明确实施批准。
- 在独立 codex/m0-rubric-real-samples 分支/worktree 中执行，不在父任务规划工作区实施；核对 main、工作区状态和范围。
- 按项目要求复制主工作区 .env，再显式隔离测试数据库/产物路径；源样本使用只读绝对路径，不复制凭证进 Git。

## 执行顺序

1. 重读父任务真实样本研究，核对两组语料的实际结构与六个 hash。
2. 在 backend/scripts 内实现可重用的样本提取/重建入口及非敏感取样规则，独立于旧验收 runner。
3. 在 backend/tests 增加解析、角色隔离、版本时点、反馈配对、终稿完整性、缺失失败和派生反例测试。
4. 使用实际两组文件生成当前 worktree 私有 fixture、manifest 和独立预期，校验完整性与来源，不调用待测生成器制造答案。
5. 记录可重建命令、输入/输出合同和脱敏结果；只提交代码与允许的元数据，不带入真实正文。
6. 完成分支与 main 复验后按 Trellis 收尾；交接以 main 上代码和源 hash 为准，不依赖将被删除的 worktree 产物。

## 质量门

```bash
git diff --check
make test
```

- 另跑新增提取器的定向测试和两组真实文件重建；新入口的实际命令由实现后写入完成证据，不把尚未存在的脚本称为已验证。
- 验证实际源文件前后 hash 相同、原产品路径没有语义变更、Git diff 无原文或凭证。
- 此子任务不跑真实模型、不重置共享数据库，不把样本构造通过称为集成或冒烟通过。

## 完成与回退

- 必须记录提交 SHA、定向/全量检查、实际语料覆盖和 main 复验结果；失败时保持任务未完成。
- 通过后仅清理本任务的 worktree/分支；下游从 main 重建其私有数据。
- 回退仅本任务的提取代码与自有临时产物，不删除用户源文件或恢复旧评分语义。
