# C5 设计：显式重置与可复验部署

## 依据与所有权

- 按 .trellis/tasks/09-05-m0-rubric-anchors-evidence/design.md 第 7.1 节及 task-map.md 执行；本任务不重复实现 C3 的逐题删除或更改评分合同。
- 重置入口放在现有 backend/scripts 的部署管理职责内，复用现有配置/迁移/检查工具；不是后台常驻任务或兼容开关。
- 现有 clear_business_data() 是隔离测试辅助，不等于跨 schema/checkpoint 的安全重置工具，不能直接充当部署 reset。

## 切换顺序

1. 取得 C4 main 验收记录，确认部署代码与当前 main 一致；核对最新 SDK、模型配置及 Docker 实际身份。
2. 在隔离资源实现和验证重置工具；保护原始样本，按父任务非 Git 产物策略准备备份/操作记录。
3. 工具代码完成分支/main 质量门后，停止本项目身份已确认的旧 API/Worker 写入，核对目标两库和活动连接。
4. 输出脱敏 dry-run，执行已授权的一次性受控备份及清理重建；只操作目标库内项目 schema，不删除整个实例/volume或轮换密钥。
5. 运行新 schema/checkpointer 准备、数据库检查与启动校验；旧数据不转换、不重放，禁止以 schema 版本号伪装数据兼容。
6. 确认空题库、首次注册及上传准备，发布实际本地服务与可复验 URL；保留诊断和回滚记录，不留下默认验收题。

## 环境与产物

- .env 保持私有；测试前复制并显式覆盖隔离目标，操作日志不打印 DSN 凭证、Cookie、token、模型正文或 AES key。
- 当前运行实例与 deploy/compose.yaml 声明可能不同；以现场为准，不为迎合旧模板重建/降级容器。
- 隔离系统验收仍使用实际 Provider/production Worker/PostgreSQL 与生产构建前端；切换后的空库/启动检查单独记录，不伪称它替代了真实生成测试。
- 私有备份/原文证据保存在父任务指定的非 Git 持久证据目录，不能仅留在即将删除的子 worktree；主工作区和源样本不作为产物写入区。
- 服务进程、工作目录、代码 SHA 和端口属于交付清单；仅管理本项目自有进程，不强杀来源不明的监听者。

## 升级与回滚

- 如果交付前出现新的正式 SDK，暂停发布，按最新版本要求重新做运行/系统验证；涉及接口或所有权变化先同步计划，不无测试升级或暗中锁旧版。
- 任一 reset 步骤失败，停止重新开放服务，按受控备份/Git 成套回退；不长期保留旧代码读取分支。
- 已删除题目的内容不能因回滚重新开放读取；恢复前应用删除边界核查，原始 .local-samples 则始终保留。
- 一次性 reset 只执行在本次确认的旧测试数据上，不循环重置未来真实上传。
