# M0 父任务最终对抗式审查

日期：2026-08-30

## 审查对象与证据等级

审查对象是当前 `main`、五个已归档子任务、父任务 PRD/design/implement，以及合并后重新运行的本地验证。没有把历史设计、Preview、HTTP 200、监听端口或 Provider Spike 单独当成产品闭环证据。

已确认：五个子任务均已归档；`main` 合并后工作区干净；`make test` 通过 53 个后端测试、前端 typecheck、OpenAPI/生成类型检查；`make build` 串行通过；三份 Git-ignored 真实样本 runner 通过；真实浏览器完成上传、角色确认、分组、场景标准/题共创、刷新恢复、组集、覆盖审查、冻结和下载；第二账号的题池/版本访问返回 403。

## 逐轮发现与修正

1. 场景合同只回写首题，第二题无法开始判定依据共创。合同确认现在在锁定 workspace 题行后传播到所有已确认任务。
2. 合同升级后旧判定依据仍被标成可用，或影响复核被严格门误挡。题读取保持严格；草稿完成老师逐题 `reviewed`/`no_conflict_confirmed` 后才可在该草稿中使用旧依据。
3. 覆盖审查可重复排队，否定风险确认会误写确认时间，无风险覆盖在 UI 上不能冻结。现已阻止同草稿并行 coverage、否定确认不产生 `confirmed_at`，无 warning 直接进入冻结。
4. 版本 ZIP 用名称集合校验，重复 Manifest 条目可能漏过。现在要求恰好四个且名称唯一，并有篡改回归。
5. 场景列表仍指向旧上传路由；题页没有场景标准入口；任务分组和版本页没有老师组集动作。现已改正入口、先合同后题共创、原生任务拆分/合并、跨批次题池和加入/移出。
6. 后台操作完成后工作台不自动刷新，窄屏导航 Escape 不关闭，长用户名造成横溢出。现已基于服务端 operation 状态轮询，补 modal 键盘焦点行为和文本截断；390px `scrollWidth == innerWidth`。
7. 已确认题引用的文件仍可修改 role/visibility，导致题 revision 与可见性边界脱钩。现已返回 `409 FILE_DISPOSITION_LOCKED`，要求新批次。
8. 标准升级提案创建新合同但不传播。现已复用合同传播逻辑，批准提案会触发所有已确认题的旧判定依据失效。
9. 根 `.env` 与 API/Worker 工作目录不一致时，`STORAGE_ROOT=./storage` 可能分裂；示例密钥名也错误。Settings 现读取仓库根 `.env`，相对存储根稳定解析，示例改用 `LANGGRAPH_AES_KEY`。
10. 前端确认分组时会丢弃 AI 提议的 attempts。现已保留原 attempt；跨组时按组生成受长度限制的可追溯 key/label。

## 父任务仍不能外推的结论

- 默认 Worker 的运行闭环使用 Fake adapter；`production_adapters` 与加密 PostgreSQL Checkpointer 工厂存在，但本轮没有把它们接入常驻 API/Worker，也没有在当前仓库启动真实 provider。父任务因此只能声明“本地 Fake 路径通过、生产运行时待部署验证”，不能声明真实 Deep Agents 已上线。
- 当前没有自动 Checkpoint 清理消费者。本轮证明手动删除已完成 thread 后业务投影仍可读；活动待答不会被本轮任何清理流程触碰，但“生产清理任务保护活动 session”仍是后续实现门禁。
- 前端没有提交 Playwright CI 套件；浏览器验收是本轮真实 CLI/人工执行。它证明当前路径，而不是持续回归保障。
- 标准升级提案和题稿结构的后端基础存在，但生产题页尚未提供完整三选项提案展示、原始批注/长期理由/受影响题的完整审核 UI；当前本地两题冻结路径不依赖该旁路。需要把它作为后续独立交付，不在本轮伪装完成。
- `DraftEditor` 的部分旧兼容组件仍在源码中，但生产路由已重定向到 M0 工作台/聚焦题页；旧 `/cases` 不应重新成为第二套生产编辑入口。
- DLP、脱敏预览、片段授权、M1 知识库和 M2 评测执行仍明确 out of scope。

## 最终判断

父任务的本地 M0 业务闭环、数据隔离、版本不可变、错误边界和跨层验收已通过；剩余事项是明确的生产部署/后续功能边界，不应被本地 Fake 验收掩盖。父任务可以在保留这些边界声明的前提下收尾，不能把它们改写成“已验证”。
